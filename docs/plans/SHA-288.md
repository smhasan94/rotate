# Implementation plan: SHA-288 npm one-time password on token delete

Accounts with 2FA on writes answer `DELETE /-/npm/v1/tokens/token/{key}`
with a 401 OTP challenge. `NpmProvider::delete` (reached from `revoke` and,
for rollback, `revoke_replacement`) maps it to a `Permanent` error carrying
`GUIDE_OTP` (SHA-298), so every npm rotation on such an account ends
`failed` at revoke with the consumers already updated. An OTP lives about
30 seconds, so it is obtained at the moment of the delete: first
`ROTATE_NPM_OTP`, otherwise a hidden prompt on the terminal, otherwise
nothing and today's failure. Nothing else about the provider changes; with
no source the behaviour is unchanged except for the wording of the error
(it can no longer say "rotate does not send one").

## Decisions

- The source is a trait, not an enum, so the provider module stays free of
  terminal code: `provider::otp::OtpSource` (new `src/provider/otp.rs`) with
  one async method, `one_time_password(&self, question: &str) ->
  Result<SecretValue, OtpError>`. `OtpError::NoSource` means "nothing to
  ask" (unset variable, variable already used, no terminal); `OtpError::
  Failed(String)` is a read or echo failure with no value in the text. The
  trait is `Send + Sync` and held as `Arc<dyn OtpSource>`, so the
  `Provider` object stays `Send + Sync`. The method is async so each
  implementation decides how it blocks; the provider only awaits.
- Two sources plus a chain in `provider/otp.rs`, none of them terminal
  code: `EnvOtp::new(var)` reads the variable lazily, on the first
  challenge, never at construction (`providers.rs` promises that building a
  registry loads no credentials), and is single-use: an `AtomicBool` set
  when a value was returned; afterwards it is `NoSource`. The process
  environment is consumed, not cleared: `std::env::remove_var` is unsound
  with other threads calling `getenv` (reqwest and the AWS SDK read proxy
  variables), rotate starts no child process, and the executor already
  tracks use. `Chain(Vec<Arc<dyn OtpSource>>)` asks each source in order
  until one returns something other than `NoSource`.
- The terminal source lives in `src/apply.rs` next to `TtyPrompt`:
  `PromptOtp` holds `Arc<Mutex<Box<dyn Prompt + Send>>>` and `Arc<Mutex<Box<
  dyn Terminal + Send>>>` and runs `prompt.read_secret(question, term)` in
  `tokio::task::spawn_blocking` (the binary's runtime is
  `new_current_thread`, so `block_in_place` is not available, and a
  blocking read on the runtime thread would stall reqwest's pool). The
  question goes to stderr through `RedactingWriter::new(io::stderr())`,
  like every other question: the `Console` is borrowed by the `Executor`
  for the whole run and cannot be shared, and `RollbackExecutor` has no
  terminal at all. `PromptError::NoTerminalForSecret` maps to `NoSource`,
  the other prompt errors to `Failed`.
- "stdin is a TTY" in the ticket is wrong for this code base and becomes
  "a controlling terminal is available". `TtyPrompt` opens `/dev/tty`, never
  stdin, precisely so `rotate apply --stdin < leaked` can still prompt; the
  OTP prompt is a second `TtyPrompt`, opened on the first challenge, so no
  check happens at build time and nothing is read before a challenge.
  Prompts never overlap: confirmation, the paste and the OTP are
  sequential, and rotations run one at a time.
- `delete` names the npm user in the question with one extra read-only
  call made only on a challenge: `GET /-/whoami` signed with the operator
  token (the OTP belongs to the operator's account, which
  `OPERATOR_REQUIREMENT` makes the leaked token's account). `revoke` and
  `revoke_replacement` do not know the user (`revoke` has only the
  credential; the scope is not passed). If whoami fails the question says
  "the npm operator account". Question text:
  `One-time password for npm user <user> to delete the token (input is
  hidden), then press Enter: `. It never contains a value or a token id.
- The redactor cannot protect an OTP: a six-digit code is under
  `redact::MIN_LEN` (8), so `SecretValue::new` registers nothing. The OTP
  is kept in a `SecretValue` for zeroizing, is never formatted (no
  `Display`, no `Debug` of the value, no tracing field), goes into a
  `HeaderValue` built from the bytes with `set_sensitive(true)` (reqwest
  prints `Sensitive` for it in any `Debug` and never indexes it in HPACK),
  and is dropped right after the retry. T8 uses a canary below `MIN_LEN` so
  the test proves this path and not the registry.
- The ticket's AC3 "current message" is kept in shape (one-time password,
  the tokens page) but the reason changes from "rotate does not send one"
  to "none was available": the guidance constant `GUIDE_OTP` is reworded
  the same way and a new `GUIDE_OTP_REJECTED` covers AC4. Both are
  `&'static str`, so they survive a resumed revoke (SHA-294 summary plus
  SHA-298 guidance).
- No `--otp` flag, no config field, no OTP on token creation (manual mode
  stays), no WebAuthn. `revoke_blocker` is unchanged: the plan cannot know
  whether the account will challenge.

## Changes

- `src/provider/otp.rs` (new, `pub mod otp` in `src/provider/mod.rs`):
  `OtpSource`, `OtpError`, `EnvOtp` (`Debug` prints the variable name and
  `used`, never a value; the value is trimmed, an empty value counts as
  unset, a value over 64 bytes or with bytes a header cannot carry is
  `Failed`), `Chain`. `pub const OTP_VAR: &str = "ROTATE_NPM_OTP"` lives in
  `src/provider/npm.rs`.
- `src/provider/npm.rs`:
  - `NpmProvider` gains `otp: Option<Arc<dyn OtpSource>>` and
    `with_otp_source(self, source: Arc<dyn OtpSource>) -> Self`. `Debug`
    prints `otp: "[none]"` or `"[set]"`.
  - `send` gains `otp: Option<&SecretValue>`; `headers(token, otp)` adds
    `npm-otp` from the bytes with `set_sensitive(true)` (a bad byte is
    `NpmError::InvalidOtp`, displayed as "the one-time password is not a
    valid HTTP header value"). GET callers pass `None`.
  - `delete(key, operator, user)`: the first DELETE is sent as today. On
    `NpmError::Status { status: 401, otp: true, .. }`: with no source, fail
    as today with the reworded text and `GUIDE_OTP`; otherwise resolve the
    user (`user`, else `whoami(operator)`, else the fallback wording),
    build the question, `await` the source, and retry the same URL once
    with the header. The retry's `Ok` or 404 is `Ok(())`; any 401 (OTP
    challenge or not) is `Permanent("{DELETE}: npm rejected the one-time
    password (401); delete the token at {page}")` with
    `GUIDE_OTP_REJECTED`; other statuses go through the existing 403 and
    `op_error` arms. `OtpError::NoSource` fails like "no source";
    `OtpError::Failed(why)` is `Permanent("{DELETE}: could not read the
    one-time password ({why}); delete the token at {page}")` with
    `GUIDE_OTP`. The `SecretValue` is dropped when the retry returns.
  - `GUIDE_OTP`: "npm requires a one-time password to delete tokens for
    this account; re-run rotate apply on a terminal to type one, or set
    ROTATE_NPM_OTP to a fresh code for one run, or delete the leaked token
    on the Access Tokens page of the npm website". `GUIDE_OTP_REJECTED`:
    "npm rejected the one-time password; re-run rotate apply with a fresh
    code (typed at the prompt or in ROTATE_NPM_OTP), or delete the leaked
    token on the Access Tokens page of the npm website".
  - Module docs: replace the "out of scope" sentence with the source order,
    the single use of the variable, the `whoami` on a challenge, and the
    `MIN_LEN` note.
- `src/apply.rs`: `PromptOtp::new(prompt, term)` and `PromptOtp::tty()`
  (a fresh `TtyPrompt::new()` and the stderr terminal); `impl OtpSource for
  PromptOtp` as decided above. `StderrTerminal` (private) implements
  `Terminal` by writing one redacted message per call.
- `src/providers.rs`: `npm_provider(config)` becomes
  `.with_otp_source(npm_otp_source())`, where `npm_otp_source()` is
  `Chain([EnvOtp::new(OTP_VAR), PromptOtp::tty()])`. Under `test-providers`
  the real-plugins scenario gains an optional `npm_otp` key with the
  grammar of `prompt` (`"panic"`, `"no_tty"`, `{"tty": path}`,
  `{"answers": [...]}`); when absent the OTP prompt follows `prompt` for
  `"panic"`, `"no_tty"` and `{"tty"}` and is `NoTty` for `{"answers"}`, so
  no binary test can ever block on the developer's `/dev/tty`. The
  variable is always chained first, in tests too.
- Docs: `docs/providers.md` npm `revoke` and `revoke_replacement` notes
  (OTP sent from `ROTATE_NPM_OTP` or a hidden prompt; a rejected or
  unavailable code fails naming the page), the npm checklist bullet and the
  "Known gaps" bullet; `docs/permissions.md` npm section (the DELETE row
  gets "plus `npm-otp` when npm asks", the OTP paragraph is rewritten, the
  variable is named as single-use and valid about 30 seconds);
  `docs/config.md` environment table row `ROTATE_NPM_OTP`;
  `docs/non-interactive.md` a bullet under "Other flags a script uses":
  the variable serves one DELETE, must be minted moments before the run,
  and so only fits a run whose revoke happens at once (no window, or the
  re-run after it; not `--wait`); `docs/usage.md` section 4 one sentence
  on the OTP prompt at revoke; README npm paragraph (last two sentences);
  `CHANGELOG.md` `[Unreleased]` "Added". `tests/provider_matrix.rs` only
  parses statuses, which do not change. No new flag or config field, so
  `tests/user_docs.rs` needs nothing. `docs/backlog.md` has no row for
  SHA-291 to SHA-298 either; none is added.

## Tests

All in `tests/npm_provider.rs` unless named otherwise; wiremock answers
the first DELETE without an `npm-otp` header with 401, `www-authenticate:
OTP` and `{"error": "otp required"}`, and a DELETE carrying `npm-otp:
<code>` with 204 (two mounts, the header match at higher priority).
`mount_whoami(&rec, &operator, "alice")` serves the question's user. A
test-local `FixedOtp(SecretValue)` and `PanicOtp` implement `OtpSource`.

- T1 (AC1) `sha288_t1_env_otp_retries_delete_with_npm_otp_header`:
  provider with `EnvOtp` over a test-only variable name set to `123456`
  (`EnvOtp::new` takes the name, so no global environment is touched by a
  parallel test); `revoke` is `Ok`; exactly two DELETEs, the second with
  `npm-otp: 123456` and `authorization: Bearer <operator>`.
- T2 (AC2) `sha288_t2_prompted_otp_is_asked_once_and_never_shown`:
  `PromptOtp::new(ScriptedPrompt::new([code]), Term)`; one question
  containing "alice" and "(input is hidden)" and not the code; the retry
  header is the code; `Ok`. The no-echo mechanism itself is `TtyPrompt`'s
  `EchoOff`, proven by `tests/apply_manual.rs`
  `pasted_value_is_not_echoed_on_the_terminal` (SHA-257 T6); a unit test
  `apply::tests::prompt_otp_without_terminal_is_no_source` covers `NoTty`.
- T3 (AC3) `sha288_t3_no_otp_source_sends_one_delete`: no source; one
  DELETE and no whoami signed with the operator token (the user is looked
  up only when there is a source to ask); `Permanent` text has "one-time
  password" and the tokens page in its `<username>` form, as today;
  `guidance() == Some(GUIDE_OTP)`. The existing
  `revoke_otp_and_bypass_refusals_fail_clearly` keeps passing.
- T4 (AC4) `sha288_t4_second_challenge_is_rejected_without_third_delete`:
  every DELETE challenged; `FixedOtp`; exactly two DELETEs; text has
  "rejected the one-time password"; `guidance() == Some(GUIDE_OTP_REJECTED)`.
  Same with the retry answered by a plain 401.
- T5 (AC5) `sha288_t5_no_challenge_never_asks`: 204 on the first DELETE,
  `PanicOtp` as source; `Ok`; no whoami signed with the operator token.
- T6 (AC6) `sha288_t6_revoke_replacement_retries_with_otp`:
  `revoke_replacement(UUID)` with `FixedOtp`; two DELETEs to
  `/-/npm/v1/tokens/token/<UUID>`, the second with the header; `Ok`.
  `tests/rollback_cli.rs` is unchanged: the executor sees only `Ok`.
- T7 (AC7) `sha288_t7_env_otp_is_single_use`: `Chain([EnvOtp, PromptOtp
  over NoTty])`; `revoke` then `revoke_replacement(UUID)` on one provider;
  three DELETEs in total, the last without `npm-otp`; the second call fails
  with `GUIDE_OTP`; the variable is still set (nothing cleared). Unit test
  `provider::otp::tests::env_otp_reads_once_and_chain_falls_through`.
- T8 (AC8), two halves:
  - `sha288_t8_otp_never_in_output_logs_audit_or_state` (in-process, like
    `tokens_never_in_output_logs_audit_or_state`): `trace_capture()`,
    `Executor` with a supplied replacement and `Term`, once with `EnvOtp`
    and once with `PromptOtp(ScriptedPrompt)`, a seven-digit canary code;
    `RunResult::Revoked`; the code and the three tokens are absent from
    `Term`, the trace capture, `audit.jsonl` and `state.json`.
  - `tests/leakage.rs` `sha288_t8_npm_otp_runs_are_clean`: a new `NpmRun`
    (wiremock registry in `rotate.yaml`, scenario `real_plugins: true`,
    canary leaked, operator and replacement tokens, `--stdin`,
    `--confirm`, `--replacement-from-env`, `-vvv` with `RUST_LOG=trace`):
    one apply with `ROTATE_NPM_OTP=<canary>` and `prompt: "panic"`, one
    with `npm_otp: {"answers": [canary]}`; exit 0, `revoked`; the `Sweep`
    over stdout, stderr and the whole root (every encoding) is clean and
    `.rotate/` modes are checked. The seven-digit canary is under
    `MIN_LEN`, so this proves the header and the error paths, not the
    registry.
- T9 (AC1, AC3) `sha288_t9_conformance_with_and_without_otp_source`:
  `provider_suite` twice: the existing fixture (no source, 204 on
  DELETE), and one whose DELETE challenges without the header and accepts
  `FixedOtp`'s code with it, so `idempotent_revoke` and `restore_outcome`
  retry on every call. Both `assert_ok()`; `errors_redacted` passes with
  the canary credential fed to `revoke`.
- Unit: `npm::tests::debug_hides_otp_source`, `headers_mark_otp_sensitive`
  (`HeaderValue::is_sensitive()`), `invalid_otp_bytes_are_refused`;
  `apply::tests::prompt_otp_runs_the_prompt_off_the_runtime`.

Checked by mutation before the PR: with the `set_sensitive(true)` on the
`npm-otp` value removed, `headers_mark_otp_sensitive` fails; with the
`used` flag removed from `EnvOtp`, T7 fails; with the OTP formatted into
the rejection text, both halves of T8 fail. `cargo fmt`, `clippy`, `test`
and `deny` run with `RUSTUP_TOOLCHAIN=1.99.0`.
