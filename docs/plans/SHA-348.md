# Implementation plan: SHA-348 apply Action follow-ups

Four decisions from the SHA-338 review: an empty plan no longer accepts
any `--confirm` id, the audit artifact can carry a suffix, `upload-audit`
learns `auto` and fails closed on public repositories, and
`--replacement-from-env` refuses operator credentials and runner
variables.

## Findings

- `rotate apply` returns "Nothing to apply." with exit 0 before
  `apply::confirm` runs (`src/main.rs`), so `--confirm rot-anything`
  passes on an empty plan. A non-empty plan with an unknown id exits 2 via
  `ConfirmError::Unknown`. Old secrets deleted by hand (`plan.skipped` with
  reason `REVOKED_BY_HAND`) keep the plan non-empty and are already known
  ids.
- The state file records every planned rotation (`rotate plan` writes
  `planned`), so "is this id finished" is `store.get(id).step == revoked`.
- The env variables rotate reads as operator credentials: `ROTATE_GITHUB_TOKEN`
  and `GITHUB_TOKEN` (`github::TOKEN_VARS`), `ROTATE_NPM_TOKEN` and
  `NPM_TOKEN` (`npm::TOKEN_VARS`), `ROTATE_NPM_OTP` (`npm::OTP_VAR`),
  `OPENAI_ADMIN_KEY` or the name in `providers.openai.admin_key_env`, and
  the AWS default chain's credential variables (`AWS_ACCESS_KEY_ID`,
  `AWS_SECRET_ACCESS_KEY`, `AWS_SESSION_TOKEN`,
  `AWS_CONTAINER_AUTHORIZATION_TOKEN`, from `aws-config`).
- The Action's upload step reads `inputs.upload-audit == 'true'` directly;
  the decision has to move into `run.sh` and reach the step as an output
  written before any fetch (the upload runs on `always()`, also when the
  step is killed mid `--wait`).
- `github.event.repository.visibility` is in `workflow_dispatch` and
  `repository_dispatch` payloads but not in `schedule` ones; the
  artifact belongs to the run's repository (`GITHUB_REPOSITORY`), which may
  differ from the `repository` input.
- `tests/action.rs` drives `run.sh` with env and arguments (`--check-inputs`)
  against wiremock; a new `--upload-decision` mode fits that harness.

## Decisions

- `apply::confirm_finished(ids, store)`: on an empty plan with `--confirm`,
  exit 0 only when every id is `revoked` in the state file; otherwise the
  same `ConfirmError::Unknown` (rotations: none), exit 2. Both before the
  audit log is opened, so no call and no audit entry either way.
- `input::check_replacement_env(name, extra)` runs before the variable is
  read: format `[A-Za-z_][A-Za-z0-9_]*`, then the deny list above plus the
  configured `admin_key_env`, then the prefixes `ACTIONS_` and `RUNNER_`.
  New variants `EnvBadName` (names nothing: a malformed name may be a
  pasted secret) and `EnvDenied` (names the deny-list entry, or the prefix
  for `ACTIONS_`/`RUNNER_` names). Exit 2.
- `run.sh` checks `replacement-env` against the same list (plus
  `ALERTS_TOKEN`, the Action's own) in `check_inputs`, before install or
  fetch, and never repeats the name.
- `audit-suffix`: `[A-Za-z0-9._-]{1,40}`, apply only. action.yml names the
  artifact `rotate-audit-<run id>-<attempt>` plus `-<suffix>` when set.
- `upload-audit`: `auto` (default), `true`, `false`. `run.sh` decides once,
  in apply mode, right after `state-dir` is set, and writes the
  `upload-audit` output the upload step reads. `auto`: the event's
  visibility (`REPOSITORY_VISIBILITY` from action.yml's `env:`), else
  `GET {api-url}/repos/{GITHUB_REPOSITORY}` with the alerts token (token on
  curl's stdin as in `fetch_alerts`); `private`/`internal` upload,
  `public` or unknown skip with a `::notice::` saying why.
  `run.sh --upload-decision` runs only the input checks and the decision,
  for the tests.
- `max-wait` stays `5h`; docs say GitHub-hosted jobs stop at 6 h.

## Tests

- T1, T2: `tests/apply_resume.rs` (seeded state, recording mocks).
- T3: unit tests in `src/input.rs`; integration in `tests/apply_manual.rs`
  with a sentinel value.
- T4 to T6: `tests/action.rs`. The SHA-338 test for "exit 0 without
  applying" now sees rotate's own exit 2.
