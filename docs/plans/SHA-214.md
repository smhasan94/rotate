# Implementation plan: SHA-214 rotate.yaml config loader

Ticket edits applied with this plan:

- The parser is `serde_norway`, the maintained fork of `serde_yaml`
  (MIT OR Apache-2.0). `serde_yaml` is published as `0.9.34+deprecated`, and
  `serde_yml` has RUSTSEC-2025-0068 (unsound, unmaintained).
  `serde_path_to_error` (dtolnay, MIT OR Apache-2.0) supplies the field path,
  because a custom type's error (a bad duration) does not name its field on
  its own.
- The GitHub Actions secret-name mapping is split into `secret_names` and
  `key_id_names`, each keyed by provider. SHA-222 added `Holds::KeyId`, and
  a name alone cannot say whether a secret holds the AWS key id or the
  secret half. Mappings add to the D4 convention; they do not replace it.
- `consumers.aws_secrets_manager.json_keys` is a list of the JSON keys
  compared and updated, where absent means every top-level string value.
  This is the ticket's "JSON key mapping"; SHA-252 owns the matching.
- Three new global flags, `--audit-log`, `--state-file` and `--overlap`,
  give AC4 something to win with. `--config` already exists.
- Relative `audit_log` and `state_file` paths resolve against the working
  directory, as D5 says, not against the config file's directory.

## Approach

`src/config.rs` holds the file schema (`FileConfig`, all `Option` with
`#[serde(deny_unknown_fields)]`), the resolved `Config`, the `Overlap`
duration type, `Overrides` and `ConfigError`. Loading is split so that tests
never touch process state:

- `Config::load(flags: &Overrides) -> Result<Config, ConfigError>` reads
  `std::env` and the current directory.
- `Config::load_with(flags, env: impl Fn(&str) -> Option<String>, cwd: &Path)`
  does the work; T4 passes a map-backed `env` instead of setting variables,
  which would race other tests.

Config file path: `--config`, then `ROTATE_CONFIG` (clap already merges
these two), then `./rotate.yaml` when it exists. A path given explicitly that
does not exist is an error; a missing default file means all defaults (AC1).
Each other setting resolves as flag, then env var, then file, then default.

`main.rs` loads the config before dispatching any subcommand. A
`ConfigError` prints to stderr and exits `Exit::Usage` (2). Subcommands
still stop at their stubs afterwards.

Rejected: `humantime` for durations, which has RUSTSEC-2025-0014
(unmaintained). The parser is about 30 lines: one or more `<integer><unit>`
groups with units `s`, `m`, `h`, `d` (`0s`, `90m`, `1h30m`, `7d`). Rejected:
resolving relative paths against the config file's directory; D5 defines
`./.rotate/` under the working directory and one rule is easier to explain.

## Schema

```yaml
overlap_window: 0s                 # Overlap
audit_log: .rotate/audit.jsonl     # path
state_file: .rotate/state.json     # path
consumers:
  github_actions:
    targets: [acme/api, "org:acme"]      # owner/repo or org:<name>
    secret_names: {github: [GH_PAT]}     # provider -> extra names (secret half / token)
    key_id_names: {aws: [CI_AWS_KEY_ID]} # provider -> extra names holding the key id
  aws_secrets_manager:
    secrets: [prod/api, "arn:aws:secretsmanager:..."]
    tag_filters: [{key: team, values: [payments]}]
    json_keys: [AWS_SECRET_ACCESS_KEY]   # absent: every top-level string
providers:
  aws: {region: us-east-1}
  github: {api_url: https://api.github.com}
  npm: {registry: https://registry.npmjs.org}
  openai: {admin_key_env: OPENAI_ADMIN_KEY}
```

Provider keys in the name maps are an enum (`aws`, `github`, `npm`,
`openai`), so a typo fails with its line. Targets parse into
`ActionsTarget::{Repo { owner, repo }, Org(name)}` and reject anything else.
URLs must start with `https://`, or with `http://` for wiremock tests. No URL
crate is used.

## Changes

- `Cargo.toml`: `serde_norway = "0.9"`, `serde_path_to_error = "0.1"`.
- `src/config.rs`:
  - `pub struct Overlap(Duration)`: `FromStr`, `Display` (canonical, for example `1h30m`), `Deserialize` through `FromStr`, `as_duration()`.
  - `pub enum ProviderName { Aws, Github, Npm, Openai }` (`serde(rename_all = "lowercase")`, `Ord`).
  - `pub enum ActionsTarget`; `pub struct GithubActionsConfig { targets, secret_names: BTreeMap<ProviderName, Vec<String>>, key_id_names: .. }`; `pub struct TagFilter { key, values }`; `pub struct SecretsManagerConfig { secrets, tag_filters, json_keys: Option<Vec<String>> }`; `pub struct ConsumersConfig`; `pub struct ProvidersConfig` with defaults from the ticket.
  - `pub struct Overrides { config, audit_log, state_file, overlap_window }` (from CLI flags).
  - `pub struct Config { overlap_window, audit_log, state_file, consumers, providers, source: Option<PathBuf> }`.
  - `#[derive(thiserror::Error)] pub enum ConfigError { Read { path, source }, Invalid { path, field, line, column, message }, Env { var, message } }`. `Invalid` reads `rotate.yaml: overlap_window at line 1, column 17: invalid duration "soon": expected <number><s|m|h|d>`.
  - `pub fn parse(text: &str, path: &Path) -> Result<FileConfig, ConfigError>`, used by the loader and T5.
- `src/lib.rs`: `pub mod config;`.
- `src/cli.rs`: global `--audit-log`, `--state-file`, `--overlap` (the latter parsed as `Overlap`), and `GlobalArgs::overrides()`.
- `src/main.rs`: load the config first and map an error to exit 2.
- `docs/rotate.example.yaml`: every field, commented.
- `tests/config.rs` (integration, `assert_cmd`): T3's CLI half.
- `tests/fixtures/config/`: `full.yaml`, `bad_duration.yaml`, `unknown_key.yaml`.

## Test mapping

Unit tests are in `src/config.rs`.

- T1 (AC1): `no_file_means_defaults` in an empty temp dir.
- T2 (AC2): `full_fixture_sets_every_field`.
- T3 (AC3): `bad_duration_names_field_and_line`, `unknown_key_names_field_and_line`; `tests/config.rs::invalid_config_exits_2`: exit 2, stderr contains `overlap_window` and `line 1`.
- T4 (AC4): `flag_beats_env_beats_file` for `audit_log`, `state_file` and `overlap_window`.
- T5 (AC5): `example_config_parses`, which also checks that the example sets every top-level field so it cannot drift.
- Extras: `overlap_parses_and_displays` (`0s`, `45s`, `90m` → `1h30m`, `1h30m`, `7d`; rejects `soon`, `10`, `1x`, `-1s`, empty), `bad_env_overlap_names_variable`, `explicit_missing_config_errors`, `targets_reject_bad_shape`, `unknown_provider_key_fails`, `api_url_must_be_http_or_https`, `rotate_config_env_selects_file`.

## Secret handling

The config holds no secret values; credentials stay in the environment.
`providers.openai.admin_key_env` is the name of a variable, never its
value. `ConfigError` may quote config text, because nothing in `rotate.yaml`
is secret by design. The example file and docs say never to put a credential
in it.

## Sequence

1. `Overlap` and its extras.
2. Schema structs, `parse`, fixtures; T2, T3 unit, T5 with the example file.
3. Resolution (`load_with`); T1, T4, env and missing-file extras.
4. CLI flags, `main.rs` wiring, `tests/config.rs`; fmt, clippy, test, deny; PR.

## Risks and unknowns

- `serde_norway` is a C-to-Rust translation of libyaml and contains `unsafe`.
  The input is the operator's own config file, not attacker-controlled
  report data. Reports are JSON and do not go through it.
- `serde_path_to_error` with `deny_unknown_fields` reports the parent path
  for an unknown key (for example `consumers.github_actions`). The message
  still names the unknown key, because serde's text includes it.

## Out of scope

Reading credentials, consumer lookups (SHA-252, SHA-253), using the values
(SHA-219 audit log, SHA-220 state store, SHA-250 planner).
