# Implementation plan: SHA-220 Rotation state store

Ticket edits applied with this plan:

- AC4 and T4: no command opens the store yet (apply is SHA-254, status
  SHA-263), so there is no CLI path that can exit 2. AC4 now says the second
  process gets `StateError::Locked` naming the lock file within 1 second, and
  that `StateError::is_usage()` is true for it, which is the contract the CLI
  maps to exit 2. T4 spawns a real child process (the test binary re-run
  with an env var) that holds the lock. The CLI exit-code check moves to
  SHA-254, the first command that opens the store for writing.
- Each consumer entry carries the consumer plugin name as well as its ref
  and status (`consumer`, `consumer_ref`, `status`). Rollback (SHA-259)
  needs the name to pick the plugin that restores it.
- The store sets `updated_at` on every `upsert` and keeps it strictly later
  than the stored one, so AC2 holds even when two upserts land in the same
  clock tick.
- T3 uses the fixed temp name `state.json.tmp` (`<state file>.tmp`). Opening
  the store for writing deletes a stale temp file; reading ignores it.

## Approach

Two modules. `src/fsutil.rs` holds the owner-only file primitives, so the
audit log (SHA-219) reuses them instead of copying them. `src/state.rs` holds
the schema and the store.

The state file is one JSON document:
`{"version": 1, "rotations": [ ... ]}`, rotations sorted by `rotation_id`
so rewrites diff cleanly. The whole file is rewritten on every `upsert`: the
file holds a handful of rotations, and a full rewrite through temp file plus
rename is what makes it atomic.

Lock: `StateStore::open` creates `<state file>.lock` (mode 0600) and takes
an exclusive advisory lock with `std::fs::File::try_lock` (flock on Linux
and macOS, stable since Rust 1.89; the crate's MSRV is 1.91). `try_lock`
does not wait, so a second process fails at once, well inside the 1 second
in AC4. The kernel drops the lock when the process exits or is killed, so a
crash never leaves a stale lock to clean up. The lock file itself is left in
place on release; deleting it would let a third process lock a new inode
while a second still holds the old one.

`StateStore::read` loads a snapshot without the lock, for `status`. Rename is
atomic, so a reader sees either the old file or the new one.

Atomic write in `fsutil::write_atomic`: create `<file>.tmp` with
`create_new` and mode 0600 (after removing a stale one), write, `sync_all`,
rename over the target, then `sync_all` on the parent directory so the rename
itself survives a power cut. Only the lock holder writes, so one fixed temp
name is enough.

Permissions: `fsutil::ensure_private_dir` creates missing parent directories
with mode 0700 and leaves existing ones alone. `fsutil::check_private`
refuses an existing file that is not a regular file (for example a symlink)
or whose mode has any group or other bit set, and the error says to run
`chmod 600`. rotate never silently tightens a mode, because a wide mode means
someone else may already have read the file.

Schema version: `version` is read first on its own. Higher than
`STATE_VERSION` (1) gives `StateError::NewerVersion`, asking for a newer
rotate. Missing or lower gives `StateError::Corrupt`; there is no older
version to migrate yet. Unknown fields are rejected so a typo in a hand edit
is not silently dropped.

Timestamps: the `time` crate (MIT OR Apache-2.0) with `serde`, `formatting`
and `parsing`, serialized as RFC 3339 UTC through `time::serde::rfc3339`.
FR20 asks for RFC 3339 in the audit log, so SHA-219 reuses it. Rejected:
`chrono` (larger, and the RFC 3339 serde helpers need extra glue), `jiff`
(fine, but newer and its dual Unlicense/MIT licence needs a note), and
`SystemTime` as integers (not readable when an operator opens the file).

Rejected: a lock crate such as `fs2` or `fd-lock` (std now has it); SQLite
(heavy for a few records); one file per rotation (several renames per step
are not atomic together); a pid file as the lock (stale after a crash).

Platform scope: Linux and macOS. Modes and flock come from
`std::os::unix`; the modules are `#[cfg(unix)]`. Windows is out of scope.

## Secret handling

`Rotation` holds `Fingerprint`s and provider-side ids only. `SecretValue` has
no `Serialize`, so a field of that type would not compile. `replacement_ref`
is documented as a public id (an AWS access key id, a token id), never a
value; the engine (SHA-254) owns what goes into it. Error messages name paths,
modes and versions, never file contents: a corrupt file's serde error is
reported by line and column only, because serde_json can quote the input.

## Test mapping

Unit tests are in `src/state.rs` and `src/fsutil.rs`, using `tempfile`.

- T1 (AC1): `state::tests::upsert_creates_private_file`: mode `0o600`, JSON contains the id; the new `.rotate` dir is `0o700`.
- T2 (AC2): `state::tests::upsert_moves_step_and_updated_at`: upsert at `created`, upsert at `consumers_updated`, reopen, assert step and `updated_at` strictly later, `started_at` unchanged.
- T3 (AC3): `state::tests::stale_temp_file_is_ignored`: valid state, garbage in `state.json.tmp`; `read` and `open` both load the valid state, and `open` removes the temp file.
- T4 (AC4): `tests/state_lock.rs::second_process_fails_fast_naming_lock`: re-runs its own test binary as a child with `ROTATE_TEST_HOLD_LOCK=<path>`; the child opens the store and waits for a release file. The parent times `StateStore::open`, asserts `< 1s`, `StateError::Locked`, message contains the lock path, `is_usage()`. Then releases the child and asserts it can open the store, and that killing a holder frees the lock (`lock_released_when_holder_dies`).
- T5 (AC5): `state::tests::list_in_progress_skips_revoked`.
- T6 (AC6): `state::tests::newer_version_refused`: `{"version": 99}`; message names 99 and asks for a newer rotate.
- T7 (AC1): `tests/state_leak.rs::secret_value_never_reaches_state_file_or_output`: canary `SecretValue`; rotation built from its fingerprint; upsert under `LogCapture`; assert the canary is absent from the state file, the temp and lock files, `Debug` of rotation, store and errors, and tracing output, and that the fingerprint is present in the file.
- Extras: `wide_mode_refused` (0644 state file), `symlink_refused`, `corrupt_file_reports_position_only`, `missing_version_is_corrupt`, `unknown_field_rejected`, `read_without_lock_while_locked`, `step_json_names`, fsutil `write_atomic_replaces_and_keeps_mode`, `open_private_append_refuses_0644`.

## Risks and unknowns

- flock is advisory and does not work across NFS on every platform. A
  `.rotate/` on a network share is unsupported; documented in the module.
- The fixed temp name relies on the lock. A process that writes without the
  lock is a bug; `write_atomic` is only called from code holding a lock.
- `rotation_id` format is the engine's choice (SHA-250); the store treats it
  as an opaque non-empty string.

## Out of scope

The engine and resume logic (SHA-250, SHA-254), `status` and `rollback`
commands (SHA-263, SHA-259), the audit log (SHA-219, which reuses
`fsutil`), migrations between schema versions, Windows.
