# Implementation plan: SHA-260 GitHub token provider

Ticket edits applied with this plan (from GitHub's current REST docs for
"Revoke a list of credentials", API version 2022-11-28):

- **`POST /credentials/revoke` must be unauthenticated.** GitHub answers
  any authenticated request with 403, so the request carries no
  `Authorization` header at all (AC5), and the provider needs no operator
  token. The endpoint allows 60 unauthenticated requests per hour and 1000
  credentials per request; a 429, or a 403 with `x-ratelimit-remaining: 0`,
  is `RateLimited` with GitHub's retry hint.
- **`ghs_` installation tokens are not revocable through that API.** The
  docs list `ghp_`, `github_pat_`, `gho_`, `ghu_` and `ghr_` only. `ghs_`
  tokens are identified, checked (`GET /installation/repositories`) and
  described, but `revoke` returns `Unsupported` with no call: "installation
  tokens expire within an hour; revoke early with `DELETE
  /installation/token` from the app". Calling that endpoint would sign with
  the leaked token, which decision D3 rules out. Manual instructions say
  "unsupported: regenerate via the app".
- **Already revoked.** The docs give 202 for an accepted batch and do not
  document an "already revoked" response: a repeat request is accepted with
  202 again. `revoke` treats 202 (and any 2xx) as success, and also a 422
  whose message says the credential was already revoked. Any other 422 is a
  permanent error (AC6).
- **`ghr_` refresh tokens cannot call the API**, so `check_valid` returns
  `Unknown` ("refresh token: GitHub has no read-only check") with no call;
  they can still be revoked.
- Tokens with no known prefix (legacy 40-hex tokens claimed only through a
  detector hint) are checked and described, but `revoke` refuses them with
  `Unsupported` and no call: rotate never posts a value to GitHub that the
  revocation API does not list.
- Verify does not retry: a token pasted by the operator works at once.
- The `x-oauth-scopes` header gives classic and OAuth app scopes. GitHub has
  no endpoint that lists a fine-grained token's permissions, so scope says
  "fine-grained: scopes not enumerable via API; check
  github.com/settings/tokens". `github-authentication-token-expiration`
  adds an `expires:` line when present.

## Approach

`src/github.rs` (shared client, SHA-253):

- `pub enum Auth<'a> { Operator, Token(&'a SecretValue), Anonymous }`.
  Header building takes it; `Token` builds `Bearer <token>` inside
  `expose_secret` and marks it sensitive, as for the operator token.
  Existing calls pass `Operator`, so the Actions consumer is unchanged.
- `get_json_as(path, auth) -> (T, HeaderMap)`, `get_paged_as(path, field,
  auth)` and `post_as(path, body: Zeroizing<Vec<u8>>, auth) -> status`.
- `impl From<GithubError> for ProviderError`, same mapping as the consumer
  one.

`src/provider/github.rs`, `GithubProvider::new(api_url)`:

- `identify`: only `Credential::Token`. A known prefix plus a token body of
  `[A-Za-z0-9_]` (20 to 255 bytes) is `High` with a GitHub detector hint
  (`Github`, `github-pat`, `github-fine-grained-pat`, and the gitleaks ids
  `github-oauth`, `github-app-token`, `github-refresh-token`) and `Medium`
  without one. A hint with no known prefix is `Low`. Key pairs and other
  shapes are `None`.
- `check_valid`: `GET /user` signed with the leaked token: 200 `Valid`,
  401 `Invalid`, rate limit and 5xx retryable errors, anything else
  `Unknown` with the status. `ghs_` uses `GET
  /installation/repositories?per_page=1`; `ghr_` makes no call.
- `describe_scope`: `GET /user` (login, `x-oauth-scopes`, expiry), then
  `GET /user/orgs` (paged) for membership names; an org read that fails is
  a line, not an error. Identity is the login. Lines: `login:`, `type:`
  (`classic`, `fine-grained`, `oauth app`, `github app user`, `github app
  installation`, `legacy`), `scopes:` or the fine-grained note,
  `expires:`, `orgs:`.
- `replacement_mode` is `Manual`; `create_replacement` is `Unsupported`
  with no call. `manual_instructions(scope)` reads the `type:` and
  `scopes:` lines it wrote and names the page: classic, the token page and
  the exact scope list (AC9); fine-grained, the fine-grained page with the
  note; app installation, "unsupported: regenerate via the app". The web
  host comes from the API URL (`api.github.com` is `github.com`; GitHub
  Enterprise Server drops `/api/v3`).
- `verify`: `GET /user` signed with the replacement; a different login
  fails naming both (AC7).
- `revoke`: shape check, then `POST /credentials/revoke` with
  `{"credentials":["<token>"]}`, no auth. The body is built in zeroized
  memory; reqwest's own copy is outside rotate's control, as for every
  request header. `restore_ref` is `None`. `revoke_many` takes many
  tokens and sends batches of 1000; `revoke` calls it with one.
- `restore`: `Ok(Unsupported)`, no call (AC8).

`src/providers.rs`: `registry_with` registers
`GithubProvider::new(config.github.api_url)` next to AWS (release builds;
`test-providers` keeps the mocks).

Rejected:

- Revoking `ghs_` with `DELETE /installation/token`: signs with the leaked
  token (D3), and the token expires within an hour anyway.
- Polling `GET /user` after revoke to confirm: the revocation is processed
  asynchronously and the extra call would use the leaked token again.
- A batch revoke across rotations in the executor: SHA-259 is changing the
  executor; `revoke_many` is ready for it.

## Secret handling

The leaked token leaves rotate in three places only: the `Authorization`
header of `GET /user`, `GET /user/orgs` and `GET
/installation/repositories` (sensitive header value), and the body of
`POST /credentials/revoke`. The pasted replacement goes only into the
`Authorization` header of `GET /user` in `verify`. Errors carry the status
and GitHub's capped `message`, never a request body. Scope lines hold the
login, type, scopes, expiry and org names.

## Test mapping

Unit tests in `src/provider/github.rs`; integration tests in
`tests/github_provider.rs` against `CallRecorder` (POST is mutating; every
GitHub read is a GET).

- T1 (AC1): `identify_each_prefix_and_not_aws` (unit, table of the six
  prefixes, hints, a key pair and an `AKIA` token).
- T2 (AC2): `check_valid_and_scope_classic`.
- T3 (AC3): `check_valid_401_is_invalid`.
- T4 (AC4): `fine_grained_scope_has_note` (unit, pure line builder) and
  `describe_scope_fine_grained` (wiremock).
- T5 (AC5): `revoke_posts_token_without_authorization`.
- T6 (AC6): `revoke_twice_already_revoked_is_ok` (202 then a 422 "already
  revoked"), plus a repeat 202.
- T7 (AC7): `verify_other_login_names_both`, and
  `executor_wrong_login_never_revokes`.
- T8 (AC8): `restore_unsupported_without_calls`.
- T9 (AC9): `manual_instructions_list_classic_scopes` (unit).
- T10 (AC2, AC5): `token_never_in_output_logs_audit_or_state`: assess, plan,
  and a full executor run with a supplied replacement at TRACE; the leaked
  and the new token appear in no table, JSON, summary, log, audit entry or
  state file, and in requests only where listed above.
- T11 (AC1 to AC8): `conformance_manual_mode` (`provider_suite`,
  `replacement_differs` skipped as manual).
- Plan safety: `plan_makes_no_state_changing_calls` (assess, build, render
  against wiremock; no POST).
- Extras: `ghs_` and `ghr_` paths, rate limit, `registry_with` registers
  `github` with the configured URL.
- Live (`#[ignore]`, `live_guard!`): `live_github_check_valid_and_scope`
  (`ROTATE_LIVE_GITHUB_TOKEN`, read-only) and `live_github_revoke`
  (`ROTATE_LIVE_GITHUB_REVOKE_TOKEN`, a throwaway token).

2. Client `Auth` and calls, with unit tests.

4. Registration, conformance, executor, leak and plan tests, live tests,

## Risks

- SHA-259 (rollback) edits `src/apply.rs` and `src/state.rs`; this ticket
  touches neither.
- GitHub may change the undocumented repeat-revoke response; the live
  revoke test catches it.
- 60 unauthenticated revokes per hour: a large incident needs
  `revoke_many`; noted for the executor.

## Out of scope

GitHub App installation token replacement, OAuth app tokens beyond revoke,
the Actions consumer, batching revokes in the executor.
