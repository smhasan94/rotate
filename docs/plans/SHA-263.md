# Implementation plan: SHA-263 `rotate status`

Ticket edits applied with this plan:

- A rollback in progress (`rollback` present, step not `rolled_back`) is
  listed by default and counts as pending (exit 3) whatever its step. This
  matters for a `revoked` rotation being rolled back: its step is terminal,
  so `list_in_progress` alone would hide it.
- `planned` rotations (written by every `rotate plan`) are listed by
  default, as `list_in_progress` does, with the hint "not started", but do
  not make the exit code 3: nothing has changed for them yet. The ticket's
  exit-3 list does not name `planned` either.
- When rotations exist but none is shown (only `revoked` or `rolled_back`,
  no `--all`), the table prints "no rotations in progress (N finished; use
  --all to show them)" and `--json` prints `[]`. An empty or missing state
  file prints "no rotations" (AC4).
- The error from the audit log is shown on its own indented line under the
  row ("last error (update, <time>): <text>"), so long provider messages do
  not widen the table. In JSON it is the row's `error` object.
- The remaining time and "after" time use seconds (`after 07:12:00 UTC`),
  not minutes as in the ticket's example: re-running at 07:12 when the time
  is 07:12:30 would still be too early.
- The clock is injectable through the scenario's `clock_offset_secs`
  (SHA-258), the same one apply uses, so T1 can put "now" anywhere relative
  to a seeded `revoke_not_before`.

## Output

Table (default), one row per rotation sorted by id:

```
ROTATION      PROVIDER  FINGERPRINT              STEP            UPDATED   CONSUMERS  REVOKE AFTER                    HINT
rot-1a2b3c4d  aws       sha256:0123456789abcdef  pending_revoke  2m ago    2/2        07:12:00 UTC (in 4m 59s)        re-run `rotate apply` after 07:12:00 UTC to revoke the old secret
rot-5e6f7a8b  npm       sha256:fedcba9876543210  failed          1h 3m ago 1/2        -                               consumer gha:org/repo:NPM_TOKEN failed: see the audit log, then re-run `rotate apply` or run `rotate rollback`
  last error (update, 2026-10-02T06:10:00Z): 403 [REDACTED github]
```

`STEP` is the state step, or `rolling_back (<step>)` while a rollback is
in progress. `CONSUMERS` is consumers with status `updated` over all
recorded consumers. `REVOKE AFTER` is shown for `pending_revoke` only: the
time in UTC (date added when it is not today) and the time left, or
`(due)` once passed.

Hints:

| state | hint |
|---|---|
| rollback in progress | rollback in progress: re-run `rotate rollback` with the same input to finish it |
| `planned` | not started: run `rotate apply` to start it |
| `created`, `consumers_updated`, `verified` | interrupted: re-run `rotate apply` with the same input to resume |
| `pending_revoke`, window open | re-run `rotate apply` after <time> to revoke the old secret |
| `pending_revoke`, window over | overlap window over: re-run `rotate apply` to revoke the old secret |
| `failed`, a consumer failed | consumer <ref> failed: see the audit log, then re-run `rotate apply` or run `rotate rollback` |
| `failed`, otherwise | failed at <failed_step>: see the audit log, then re-run `rotate apply` or run `rotate rollback` |
| `needs_rollback` | run `rotate rollback` with the same input, then `rotate apply` again |
| `revoked` | done |
| `rolled_back` | rolled back |

`--json` prints a JSON array, one object per row, with the same fields:
`rotation_id`, `provider`, `fingerprint`, `step`, `rollback_in_progress`,
`updated_at` (RFC 3339), `updated_seconds_ago`, `consumers_updated`,
`consumers_total`, `revoke_not_before` (RFC 3339 or null),
`revoke_remaining_seconds` (null unless `pending_revoke`), `failed_step`,
`pending`, `hint`, `error` (`{step, at, text}` or null). Documented in
`docs/status-schema.json` in the style of `docs/plan-schema.json`.

## Exit codes

- 3 when any rotation in the state file is pending: step `pending_revoke`,
  `failed`, `needs_rollback`, `created`, `consumers_updated` or
  `verified`, or a rollback in progress. Computed over every rotation,
  shown or not.
- 0 otherwise, including no state file, an empty one, and only `planned`,
  `revoked` or `rolled_back` rotations.
- 2 when the state file cannot be used (wide mode, newer version, corrupt),
  as for the other commands. 1 for a plain I/O error.

## Approach

`src/status.rs` (new, `#![cfg(unix)]` like `state`): pure functions with
no provider, consumer or network types in their signatures.

- `last_errors(entries) -> (BTreeMap<String, LastError>, Vec<String>)`:
  the last audit entry per rotation id, kept when it has an `error`;
  unreadable lines become one warning, never a failure. The text is a
  `RedactedText`, which redacts again when read back from JSON.
- `rows(snapshot, errors, now, all) -> Vec<StatusRow>`; `any_pending`;
  `render_table(rows, finished, now)`; `render_json(rows)`.

`src/cli.rs`: `Command::Status(StatusArgs { all })`.

`src/main.rs`: `status()` reads the state with `StateStore::read` (no
lock, no write), reads the audit log with `audit::read_all` (a wide-mode
or unreadable audit log is a warning on stderr; rows are still shown),
uses `providers::clock()` or the system clock, prints through the console
and returns the exit code. It builds no registry and starts no runtime.

`docs/status-schema.json`, README (usage, exit codes, remove from "Not
done yet").

## Secret handling

Status reads no secret: it has no input, and the state file and audit log
hold fingerprints and refs only. The one free text it prints, the audit
`error`, is a `RedactedText` re-redacted on read, and every byte goes
through the redacting console. T7 seeds an audit error holding a
provider-shaped canary token and checks stdout, stderr at `-vvv`, the
state file and the audit log (unchanged bytes) for it.

## Risks

- SHA-267 refactors `tests/e2e_aws.rs` helpers in parallel; this branch
  only removes the `#[ignore]` on one test.
- Clock skew between the machine that wrote the state and the one running
  status shifts the remaining time; status reports it by its own clock.

## Out of scope

Changing state, contacting providers, filtering by provider or id,
following (`--watch`).
