# Implementation plan: SHA-212 CI workflow with fmt, clippy, test and cargo deny

Ticket edits applied with this plan: AC4 and T4 replaced with a self-contained
`cargo deny` self-test (allowlist without MIT); T2, T3 and T5 marked as
one-time verifications linked from the PR.

## Approach

One workflow `ci.yml` with four separate jobs (`fmt`, `clippy`, `test`,
`deny`), each over an `os` matrix of ubuntu-latest and macos-latest with
`fail-fast: false`, so a red fmt job never hides the others (AC2) and "four
green jobs per OS" (AC1) holds literally. `deny.toml` starts with the license
allowlist from the ticket and advisories on.

Rejected: one job with four steps and `continue-on-error`. Cheaper, but the
per-check status is buried inside one job, which breaks AC2 and makes branch
protection coarse. Rejected: fmt and deny on Linux only. The ticket says all
four on both platforms and macOS is a release target.

## Changes

- `.github/workflows/ci.yml`: triggers `pull_request` and `push` to main;
  `concurrency` cancels superseded runs; `permissions: contents: read`. Jobs:
  - `fmt`: dtolnay/rust-toolchain@stable with rustfmt;
    `cargo fmt --all -- --check`.
  - `clippy`: toolchain with clippy; Swatinem/rust-cache@v2;
    `cargo clippy --all-targets --all-features -- -D warnings`.
  - `test`: rust-cache; `cargo test --all-features` with
    `RUSTFLAGS: -D warnings` (covers SHA-194 AC1).
  - `deny`: EmbarkStudios/cargo-deny-action@v2 on Linux;
    taiki-e/install-action@cargo-deny then `cargo deny check` on macOS; plus
    the T4 self-test step.
- `deny.toml`: `[licenses] allow = ["Apache-2.0", "MIT", "BSD-2-Clause",
  "BSD-3-Clause", "ISC", "Unicode-3.0", "Zlib"]`; `[advisories]
  yanked = "deny"`; `[bans] multiple-versions = "warn"`; `[sources]
  unknown-registry = "deny"`.
- `ci/deny-selftest.toml`: same file with MIT removed (T4 fixture).
- `CONTRIBUTING.md`: one paragraph on branch protection (all eight checks
  required) if the file exists; otherwise SHA-213 adds it.

## Secret handling

No secrets are used. The workflow sets `permissions: contents: read` and never
echoes the environment. Live tests are `#[ignore]` (SHA-216), so no real
credential is ever needed in default CI.

## Test mapping

- T1 (AC1): the PR that adds the workflow shows eight green jobs. No code test.
- T2 (AC2), T3 (AC3), T5 (AC5): one-time red branches; the PR description
  links each run.
- T4 (AC4): CI step `cargo deny check licenses --config ci/deny-selftest.toml`
  wrapped so a non-zero exit is success, and its output grepped for `clap`.
  Runs on every CI run.
- Extra: the `deny` job on the real `deny.toml` is the AC1 deny check.
- None need wiremock or live credentials.

## Sequence

1. `deny.toml`; run `cargo deny check` locally on the SHA-194 tree; adjust the
   allowlist until green.
2. `ci.yml` with the four jobs; push branch; confirm eight green jobs.
3. Add `ci/deny-selftest.toml` and the self-test step; confirm still green.
4. Throwaway branches for T2, T3, T5; record links; delete branches.
5. Enable branch protection on main requiring the eight checks.

## Risks and unknowns

- Transitive licenses: reqwest with rustls pulls `webpki-roots` (MPL-2.0) and
  `ring` (ISC plus OpenSSL-style). They arrive in SHA-221 or later, but the
  allowlist will need a decision then. Find out early by running
  `cargo deny check licenses` on a scratch tree that adds reqwest and
  aws-sdk-sts before those tickets start. Follow-up filed as a Later ticket.
- macOS runner minutes cost about ten times Linux. Accept for now.
- cargo-deny-action does not support macOS. If install-action is unavailable,
  fall back to `cargo install cargo-deny --locked` with rust-cache.

## Out of scope

Release workflow (SHA-215). Coverage, dependabot, CodeQL. Follow-up ticket
filed: "Later: license allowlist decision for MPL-2.0 and ring before adding
reqwest".
