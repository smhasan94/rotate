# Implementation plan: SHA-252 AWS Secrets Manager consumer

Ticket edits applied with this plan:

- Client request token. The `Consumer` trait does not carry the rotation id
  (`update(target, new)`), and changing the trait would touch every consumer
  and SHA-254. The token is derived instead from the consumer ref, the
  version id the secret is at before the write, and the fingerprint of the
  value written: `rotate-` plus 40 hex characters of sha256 over those. A
  retry of the same write against the same starting version sends the same
  token, so Secrets Manager treats it as one write. AC4 now reads: "Given
  `update` called twice for the same match and replacement while the secret
  is at the same version, then both `PutSecretValue` requests carry the same
  client request token; and given the secret already holds the replacement
  at every recorded path, `update` writes nothing and returns the current
  version."
- AC5: the last `PutSecretValue` body "parses to the same JSON object as the
  original, keys in the original order". Whitespace is not kept: rotate
  writes compact JSON.
- AC7 covers every value the operator cannot read (`AccessDeniedException`,
  `DecryptionFailure`): the entry is listed as matched by name and not
  updatable, with the error code and AWS message as the reason, because
  rotate cannot tell whether it holds the secret and must not revoke while
  it might. A configured name that does not exist
  (`ResourceNotFoundException`, or `InvalidRequestException` for a secret
  scheduled for deletion) is skipped with a warning. Throttling and other
  errors fail `find`; the planner shows that as a lookup error (SHA-250).
- T9 runs at library level: find, update and restore through the consumer
  against wiremock with tracing captured at TRACE (the SDK's own events
  included), plus `Debug` and `Display` of every match, receipt and error.
  The CLI and audit-log half is SHA-264's end-to-end test: no real provider
  is registered yet, so `rotate plan` never reaches a consumer without the
  `test-providers` mocks.
- Field paths are top-level JSON keys only, matching
  `consumers.aws_secrets_manager.json_keys` ("every top-level string
  value"). Nested objects are kept unchanged and never searched.

## Approach

`src/consumer/aws_secrets_manager.rs`, `SecretsManagerConsumer`, name
`aws-secrets-manager`.

Construction makes no call and loads no credentials:
`SecretsManagerConsumer::new(config: SecretsManagerConfig, region:
Option<String>)` keeps the config and an empty `tokio::sync::OnceCell` for
the client. The client is built on the first call that needs it with
`aws_config::defaults(BehaviorVersion::latest())` plus the configured region,
so the standard environment applies (credentials chain, `AWS_REGION`,
`AWS_ENDPOINT_URL_SECRETS_MANAGER`). `with_client(config, client)` is for
tests: an SDK client pointed at wiremock with static fake credentials.
When `secrets` and `tag_filters` are both empty, `find` returns no matches
and builds nothing.

`find(secret)`:

1. Candidates: `secrets` in order, then for each tag filter a paginated
   `ListSecrets` with filters `tag-key = key` and, when values are given,
   `tag-value = values`. AWS applies the two filters to any tag, so each
   entry's tags are checked locally for a tag with that key and an accepted
   value. Filters are a union; entries are deduped by name and ARN.
2. For each candidate, `GetSecretValue`. The `SecretString` is moved into a
   `SecretValue` at once (`SecretBinary` likewise, compared as plain bytes).
3. Plain value: matches when its fingerprint equals `secret.fingerprint`;
   path `$`, holds `Secret`.
4. JSON object: parsed into `SecretDocument`, an ordered list of
   `(key, Field)` where `Field::Secret(SecretValue)` holds every string
   value and `Field::Other(serde_json::Value)` every non-string value. A
   custom `Deserialize` puts strings straight into `SecretValue`; no
   `serde_json::Value` ever holds a top-level string. Keys considered are
   `json_keys` when set, else all. Secret paths: keys whose value has the
   leaked fingerprint. If there are any and the `SecretRef` has a key id,
   key id paths: keys whose value equals the key id. Holds `KeyPair` when
   both are present, `Secret` otherwise.
5. One `ByValue` match per entry, consumer ref
   `aws-secrets-manager:<name or ARN>#<secret paths>[|<key id paths>]`, for
   example `aws-secrets-manager:prod/app#$.AWS_SECRET_ACCESS_KEY|$.AWS_ACCESS_KEY_ID`.
   Secret ids cannot contain `#`; `%`, `,` and `|` in a key are
   percent-encoded. The ref is how `update` and `restore` (possibly in a
   later process, after an overlap window) know the paths, so it is parsed
   back, never looked up in memory.

`update(target, new)` and `restore(target, old)` share `write`:
refuse a not-updatable match (`NotUpdatable`); refuse a token for a
`KeyPair` match (`Unsupported`, via `value_fingerprint`); read the current
value and version with `GetSecretValue`; replace the value at each recorded
path (secret paths get the secret, key id paths the key id; a path that is
gone or no longer a string is a `Permanent` error naming the key, "re-run
plan"); skip the write if nothing changes; otherwise `PutSecretValue` with
the new document and the derived token. The receipt carries the new
`VersionId`. Restore writes the old value back the same way, as a new
version (`AWSCURRENT` moves back); it never relabels old versions, so it
works even if the earlier version was deleted.

Errors are mapped from the SDK error code: throttling to `RateLimited`;
dispatch failures, timeouts, `InternalServiceError` and 5xx to `Transient`;
everything else to `Permanent` with `<operation> <secret id>: <code>:
<message>`. No error text includes a request body.

Holds decision: an AWS pair stored as two JSON keys is one `KeyPair` match
(both keys rewritten in one `PutSecretValue`, one version, never a half
updated pair). An entry holding only the key id is not matched: Secrets
Manager matching is by the secret's fingerprint (D4), and a key id alone is
not a credential. A plain entry holding the secret is `Secret`.

Rejected: keeping found paths in memory between `find` and `update` (lost
across the exit-and-resume overlap window, D2); `serde_json::Value` for the
whole document (top-level secrets would sit in plain `String`s);
`UpdateSecretVersionStage` for restore (fails if the old version was
removed, and needs the version id stored somewhere); one shared AWS helper
module (SHA-251 builds its own client; a helper can come later); matching
key id only entries.

Registration: `providers::consumers` takes `&Config` so the consumer gets
`consumers.aws_secrets_manager` and `providers.aws.region`; non-feature
builds register it. With `test-providers` the scenario mocks stay the only
consumers, so CLI tests remain deterministic. `src/main.rs` changes only the
call site (`providers::consumers(config)`).

## Secret handling

Values from `GetSecretValue` go into `SecretValue` before anything else
touches them; the SDK output's own `String` is dropped right after (the SDK
redacts it in `Debug`). JSON strings deserialize straight into `SecretValue`.
The document written by `PutSecretValue` is built in a `Zeroizing` buffer
sized up front and handed to the SDK inside one closure; the SDK's copy in
the request body is outside rotate's control. Matches, refs, reasons,
receipts and errors hold names, key names, fingerprints, version ids and AWS
error codes only. Residual risk: serde_json's scratch buffer for escaped
strings is not wiped.

  and render keeps order and non-string values, `json_keys` restriction,
  token derivation, error mapping.

## Sequence

1. Dependencies, `cargo deny check`.
2. Document type, ref format, token; unit tests.
3. Client, `find`, `write`; wiremock tests T1 to T9.
4. Conformance T10, registration, docs, all checks, smoke, PR.

## Risks

- `src/providers.rs` and the `consumers()` call site in `src/main.rs` are
  touched by SHA-253 (it needs config too) and SHA-254. Identical
  `consumers(config)` signatures merge cleanly; otherwise the second to land
  merges.
- `Cargo.lock` grows by the AWS SDK tree and conflicts with SHA-251; take
  main's lock and rebuild.
- Build time: `aws-lc-sys` compiles C on first build.

## Out of scope

Creating secrets, Secrets Manager rotation lambdas, nested JSON paths,
key id only entries, cross-region or cross-account candidates beyond what
the client's credentials and region reach, the GitHub Actions consumer
(SHA-253).
