# Implementation plan: SHA-213 README, CONTRIBUTING, SECURITY.md and PR template

Ticket edits applied with this plan:

- T1 and T2 run as one script, `ci/check-docs.sh`, in a new Linux-only
  `docs` job in `ci.yml`. The checks read text, so one OS is enough.
- T3 is a one-time check after merge. GitHub fills the template from the
  default branch, so the PR that adds it cannot show it. The first PR opened
  in the web UI after merge is the evidence.
- SECURITY.md names GitHub private vulnerability reporting as the channel.
  It is off for the repo today; the owner turns it on (Settings, Security).
  No email address is published.

## Approach

Docs only, plus one small shell script. README is honest about the
pre-release state: `rotate plan` reads a TruffleHog or gitleaks report or one
secret on stdin and prints an assessment; no real provider exists yet, and
`apply`, `rollback` and `status` are stubs. The four safety guarantees come
from the brief (never printed or stored, zeroized; dry run makes no changes;
failure stops before revoke; no revoke with un-updated consumers without
`--force`).

CONTRIBUTING gains general sections at the top (setup, the four checks,
branches, commits, pull requests, dependencies). The existing "Writing
tests", "Handling secret values", "Adding a provider" and "Adding a
consumer" sections are left as they are; SHA-249 owns the last two.

Rejected: a Rust test that reads the docs. A docs check does not belong in
`cargo test`, and a shell script in `ci/` sits next to the deny self-test.

## Changes

- `README.md`: description, CI badge, status note, safety guarantees, build
  from source, quick start placeholder (`rotate plan report.json`), links to
  `docs/requirements.md`, `docs/report-formats.md`,
  `docs/rotate.example.yaml`, CONTRIBUTING and SECURITY, license.
- `CONTRIBUTING.md`: replace the stub intro with setup, "Checks" (the four
  commands in one `sh` block, copied from CLAUDE.md), branch naming,
  conventional commits, PR-only rule with the plans/backlog exception,
  required CI checks, license note for new dependencies.
- `SECURITY.md`: supported versions (none released yet), private channel,
  what to include, never send a live secret, response targets, scope, the
  promise that secret values are never logged.
- `.github/pull_request_template.md`: Linear link, What, T-cases table, and a
  checklist (ticket linked, T-cases added, four checks pass, no secret values
  or secret-shaped literals in tests, fixtures or output, docs updated).
- `ci/check-docs.sh`: T1 greps README for `dry run`, `zeroized`, `revoke`
  and SECURITY for `report`; T2 extracts the first `sh` block under
  `## Commands` in CLAUDE.md and under `## Checks` in CONTRIBUTING and
  diffs them. Exits non-zero with a message on any miss.
- `.github/workflows/ci.yml`: `docs` job on ubuntu-latest running the script.

## Test mapping

- T1 (AC1, AC4): `ci/check-docs.sh`, docs job. Checked locally that removing
  a word fails it.
- T2 (AC2): same script; checked locally that editing one command fails it.
- T3 (AC3): after merge, open a PR in the web UI and confirm the checklist is
  in the description.

## Out of scope

Usage docs (Epic 7), provider matrix (Epic 6), enabling private
vulnerability reporting (a repo setting for the owner).
