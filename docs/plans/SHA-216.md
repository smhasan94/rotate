# Implementation plan: SHA-216 Test harness conventions

Ticket edits applied with this plan: AC5 and T5 added for read-only predicates
(AWS uses POST for read-only calls); T4 marked as live-only.

## Approach

Integration-test helpers in `tests/common/mod.rs`, shared by every test binary
under `tests/`. The wiremock helper wraps a `MockServer`. The call recorder is
built on `MockServer::received_requests()` rather than custom middleware and
classifies each request as mutating by HTTP method unless a registered
read-only predicate matches. The live gate is `#[ignore]` on the test plus a
`live_guard!()` macro that returns early unless `ROTATE_LIVE_TESTS=1`.

Rejected: a `testkit` module in `src/` behind a feature. Better sharing with
unit tests, but there is no `lib.rs` yet and mocks of the Provider trait belong
with the trait (SHA-221); revisit there. Rejected: a custom wiremock `Respond`
that records calls; it duplicates what `received_requests` already gives.

## Changes

- `Cargo.toml` dev-deps: `wiremock`, `tokio` (rt-multi-thread, macros),
  `tempfile`, plus `assert_cmd` and `predicates` from SHA-194.
- `tests/common/mod.rs`:
  - `pub async fn mock_server() -> MockServer`;
    `pub fn base_url(&MockServer) -> String`.
  - `pub struct RecordedCall { pub method, pub path, pub query,
    body: Vec<u8>, pub mutating: bool }` with `pub fn body(&self) -> &[u8]`
    and a manual `Debug` printing method, path, query and body length only.
  - `pub struct CallRecorder { server, read_only: Vec<Box<dyn
    Fn(&wiremock::Request) -> bool + Send + Sync>> }` with
    `mark_read_only(pred)`, `async fn calls() -> Vec<RecordedCall>`,
    `async fn assert_no_mutations()` whose panic message lists method and path
    of each mutating call and never a body.
  - `pub struct TestDirs { root: TempDir, rotate_dir: PathBuf }` with
    `TestDirs::new()` creating `.rotate/`.
  - `#[macro_export] macro_rules! live_guard` that returns from the test with
    `eprintln!("skipped: ROTATE_LIVE_TESTS not set")` unless the variable
    equals "1"; `pub fn require_env(name) -> Option<String>` for later live
    tests.
- `tests/harness.rs`: the self-tests.
- `tests/live_smoke.rs`: one `#[ignore] #[test] fn live_smoke()` using the
  guard, asserting only that the variable is present.
- `CONTRIBUTING.md`: section "Writing tests" (unit in `src`, integration in
  `tests`, wiremock pattern, live pattern and how to run).

## Secret handling

Recorded calls hold raw request bodies because later tests must inspect them
(for example a PutSecretValue body). The harness keeps them out of every
default output path: `Debug` prints lengths, `assert_no_mutations` prints
method and path only, and nothing in `common` logs. Tests that want a body
call `body()` explicitly. Bodies live in test memory only and are dropped with
the recorder. No zeroization here because these are test doubles, never real
secrets, and the leakage audit (SHA-265) covers the real paths.

## Risks and unknowns

- `received_requests()` returns `None` when the server was started with
  recording off. Construct with `MockServer::start()` (records by default);
  check in step 2.
- `catch_unwind` across an async test needs the assertion in a sync block.
  Take the snapshot with `.await` first, then assert synchronously.

## Out of scope

Mock provider and consumer (SHA-221, SHA-222). A shared `testkit` feature for
unit tests: revisit in SHA-221; no ticket filed.
