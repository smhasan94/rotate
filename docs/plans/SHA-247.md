# Implementation plan: SHA-247 Input selection: report file or a single secret on stdin

Ticket edits applied with this plan:

- This ticket owns all of `rotate`'s input. The report path argument and
  `--format` move here from SHA-250, so that SHA-248 and SHA-250 receive
  findings from one place: `rotate plan [REPORT] [--format F]` or
  `rotate plan --stdin [--provider P]`. The same arguments apply to
  `apply` and `rollback`.
- Until SHA-248 lands, `plan` prints the findings it read (count, then one
  line each with fingerprint, detector and source) and then the
  not-implemented stub, exit 2. AC1's "reaches the planner" is tested on that
  output. SHA-248 replaces it with the assessment table.
- The "test feature" is a cargo feature, `test-providers`. It registers four
  `MockProvider`s named `aws`, `github`, `npm` and `openai` in the CLI's
  registry, so T1 and T3 have providers to name before the real ones exist
  (SHA-251, SHA-260 to SHA-262). CI runs `--all-features`, so the tests run
  there. Release builds never enable it.
- `--provider` requires `--stdin`. Forcing one provider onto every finding in
  a report is not a use case.
- An AWS pair is recognised by shape, not only when `--provider aws` is
  given: if the input is `<AWS key id>:<secret>` or `<AWS key id>\n<secret>`,
  where the key id is `AKIA`/`ASIA` plus 16 uppercase alphanumerics, the key
  id goes to `extra.access_key_id` and the rest becomes `raw`.
- T6 greps stdout and stderr. The binary has no tracing subscriber
  (SHA-218) and no audit log (SHA-219) yet, so those two have nothing to grep.

## Approach

- `src/input.rs` (lib): `read_secret(reader) -> Result<Finding, InputError>`
  reads all of stdin into a `SecretValue` through `SecretValue::from_reader`
  (zeroized buffer), trims one trailing `\n` or `\r\n`, rejects empty input,
  splits an AWS pair, and returns a `Finding` with `detector = "stdin"` and
  `source = SourceLocation::file("stdin")`. `stdin_hint(is_terminal, &mut
  impl Write)` writes `Reading the secret from stdin: paste it, then press
  Ctrl-D.` when stdin is a terminal.
- `src/cli.rs`: `Plan`, `Apply` and `Rollback` carry `InputArgs { report:
  Option<PathBuf> (positional), format: Option<ReportFormat> (requires
  report), stdin: bool (conflicts with report), provider: Option<String>
  (requires stdin) }`. `Status` takes none. `rotate` with no subcommand is
  still `plan`.
- `src/providers.rs` (binary): `registry() -> ProviderRegistry`, empty in a
  normal build and four named mocks under `test-providers`.
- `src/main.rs`: after config, for `plan`, `apply` and `rollback`:
  1. Check `--provider` against `registry().names()` first, before reading
     stdin. If it is unknown, exit 2 with `unknown provider "nope"; known
     providers: aws, github, npm, openai` (or `none are built in yet`).
  2. Read the input: the stdin hint then `read_secret`, or `read_report`.
     With neither, exit 2 with `no input: pass a report path or --stdin`.
     Report warnings print to stderr through their `Display`, which never
     includes content.
  3. Print the findings summary to stdout, then the stub.

Rejected: reading the secret with a hidden-input prompt (rpassword) when stdin
is a TTY. The ticket asks for a hint and Ctrl-D, and manual replacement
(SHA-257) owns the hidden prompt. Rejected: a `--report` flag instead of a
positional argument. `rotate plan trufflehog.json` reads naturally and
matches the other scanners.

## Secret handling

The secret is read into a pre-reserved zeroized buffer. Trimming and
splitting copy into new `SecretValue`s; the key id is copied to a plain
`String` because it is not secret. Nothing from stdin is printed: errors say
`no secret on stdin` and never echo input, and the summary prints
fingerprints only. clap never sees the secret, because it arrives on stdin
and not as an argument (the existing unknown-argument guard in `main.rs`
stays).

3. `main.rs` input flow and summary; `tests/stdin.rs`; fmt, clippy, test, deny; PR.
