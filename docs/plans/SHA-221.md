# Implementation plan: SHA-221 Provider trait, registry and MockProvider

Ticket edits applied with this plan:

- Methods take `&Credential` instead of `&SecretValue`. An AWS request cannot
  be signed with the secret access key alone, so the trait input must carry
  the key id too. `Credential` is `Token(SecretValue) | KeyPair(SecretPair)`.
- `revoke` returns `Revoked { restore_ref: Option<String> }` instead of `()`,
  so the engine has something to hand back to `restore` (the deactivated AWS
  key id). `restore` takes that `&str`.
- The `Finding` model from SHA-223's scope is defined here (`src/finding.rs`)
  because `identify` needs it; SHA-223 adds the parsers only.
- The mutating list is a free `pub const MUTATING: &[&str]` in the provider
  module rather than an associated const, which would make the trait not
  object-safe.
- Failure injection is a per-method queue plus a per-method "always" slot, so
  SHA-248 can script `429, 429, Valid` without a new mock.
- T7 is an integration test (`tests/provider_leak.rs`) so it sees the crate
  as the engine will; the tracing capture helper moves from
  `tests/secret_leak.rs` into `tests/common`.

## Approach

`src/provider/mod.rs` holds the trait, its value types, the error type and
`ProviderRegistry`. `src/provider/mock.rs` holds `MockProvider`.
`src/calls.rs` holds `Call` and `CallLog`, the shared recorder that
`MockConsumer` (SHA-222) reuses. `src/finding.rs` holds `Finding` and
`SourceLocation`. All are compiled unconditionally: the mock is a public
test double used by unit tests, integration tests and later the conformance
suite, and it pulls in nothing the binary does not already have.

The trait uses `async_trait` so `Box<dyn Provider>` works. `identify` is
synchronous (pattern and hint matching, no IO) and `replacement_mode` and
`name` are plain methods.

Rejected: native `async fn` in traits. Not object-safe, and the registry
must hold heterogeneous providers. Rejected: a `mock` cargo feature; it
would force every test invocation to pass `--features` and gains nothing
at this size. Rejected: `identify(&SecretValue)` only; the detector hint from
the report is the strongest signal and lives on the finding.

## Changes

- `Cargo.toml` deps: `async-trait`, `thiserror`. Both MIT or Apache-2.0.
- `src/finding.rs`:
  - `pub struct SourceLocation { pub file: String, pub line: Option<u64>, pub commit: Option<String> }`, `Display` as `file:line@commit` with missing parts omitted.
  - `pub struct Finding { pub raw: SecretValue, pub detector: String, pub source: SourceLocation, pub extra: BTreeMap<String, String> }`. `extra` is for non-secret metadata such as `access_key_id`; anything secret stays in `raw`.
  - `Finding::credential(&self) -> Credential`: `KeyPair` when `extra` has `access_key_id`, else `Token`. `Finding::fingerprint()`.
  - Derived `Debug`, `Clone` (safe: `SecretValue` prints its fingerprint).
- `src/provider/mod.rs`:
  - `pub enum Credential { Token(SecretValue), KeyPair(SecretPair) }` with `secret()`, `fingerprint()`, `key_id()`.
  - `pub enum Confidence { Low, Medium, High }` (`Ord`).
  - `pub enum Validity { Valid, Invalid, Unknown { reason: String } }`.
  - `pub struct Identity(pub String)`; `pub struct Scope { pub identity: Identity, pub lines: Vec<String> }`.
  - `pub struct Replacement { pub credential: Credential, pub replacement_ref: String }` (no `Serialize`; it holds a secret).
  - `pub struct Revoked { pub restore_ref: Option<String> }`.
  - `pub enum RestoreOutcome { Restored, Unsupported }`.
  - `pub enum ReplacementMode { Automatic, Manual }`.
  - `pub enum ProviderError { RateLimited { retry_after: Option<Duration> }, Transient(String), Permanent(String), Unsupported(String) }` via `thiserror`, plus `is_retryable()` (RateLimited and Transient) for SHA-248.
  - `pub const MUTATING: &[&str] = &["create_replacement", "revoke", "restore"]` and `pub fn is_mutating(method: &str) -> bool`.
  - `#[async_trait] pub trait Provider: Send + Sync { fn name(&self) -> &'static str; fn replacement_mode(&self) -> ReplacementMode; fn identify(&self, finding: &Finding) -> Option<Confidence>; async fn check_valid(&self, credential: &Credential) -> Result<Validity, ProviderError>; async fn describe_scope(&self, ..) -> Result<Scope, ..>; async fn create_replacement(&self, ..) -> Result<Replacement, ..>; async fn verify(&self, credential: &Credential, identity: &Identity) -> Result<(), ..>; async fn revoke(&self, credential: &Credential) -> Result<Revoked, ..>; async fn restore(&self, restore_ref: &str) -> Result<RestoreOutcome, ..>; }`.
  - `pub struct ProviderRegistry { providers: Vec<Arc<dyn Provider>> }`: `new()`, `register(impl Provider + 'static)`, `get(&str)`, `names()`, `identify(&Finding) -> Result<Option<Identified>, AmbiguousProvider>` where `Identified { provider: Arc<dyn Provider>, confidence }` and `AmbiguousProvider { confidence, names: Vec<&'static str> }` implements `Error`. Highest confidence wins; two or more at the top is an error naming all of them.
- `src/calls.rs`:
  - `pub struct Call { pub target: String, pub method: String, pub mutating: bool, pub fingerprint: Option<Fingerprint> }`, derived `Debug`, `Clone`, `PartialEq`.
  - `#[derive(Clone, Default)] pub struct CallLog(Arc<Mutex<Vec<Call>>>)`: `record(Call)`, `calls() -> Vec<Call>`, `len()`, `is_empty()`, `mutating() -> Vec<Call>`, `assert_no_mutations()` (panics listing target and method), `clear()`.
- `src/provider/mock.rs`:
  - `pub struct MockProvider` built with `MockProvider::new(name)` then `.identify_prefix(&str)`, `.confidence(Confidence)`, `.validity(Validity)`, `.scope(Scope)`, `.restore_outcome(RestoreOutcome)`, `.replacement_mode(ReplacementMode)`, `.log(CallLog)` (share a log across mocks), `.fail_next(method, err)`, `.fail_always(method, err)`. Replacements are generated as `"<prefix>replacement-<n>"` with a counter so each is distinct and `replacement_ref` is `"<name>-ref-<n>"`.

  - `log()` returns the shared `CallLog`. `Debug` for `MockProvider` prints name and call count only.

## Secret handling

`Call` stores a `Fingerprint`, never a value. The mock keeps no copy of any
credential it receives; the generated replacement is a `SecretValue` and the
mock forgets it once returned. `Replacement`, `Credential` and `Finding`
have no `Serialize` impl because they contain a `SecretValue`, so the
compiler enforces that they never reach the audit log. `AmbiguousProvider`
and `ProviderError` messages carry provider names and reasons written by
the provider; the real providers (SHA-251, SHA-260 to SHA-262) own keeping values out of
those strings and the redaction layer (SHA-218) is the backstop.

## Risks and unknowns

- `async_trait` boxes every future; irrelevant at rotate's call volume.
- `Arc<dyn Provider>` plus `Send + Sync` supertraits: the mock holds a
  `Mutex`, so it is `Sync`; a real provider holding a `reqwest::Client` is
  too.
- `Finding` shape may need to change when the parsers land; it is `pub` with
  `pub` fields so SHA-223 can extend it without touching this module.

## Out of scope

Real providers (SHA-251, SHA-260 to SHA-262), the Consumer trait (SHA-222), the
conformance suite (SHA-249), retry and concurrency (SHA-248).
