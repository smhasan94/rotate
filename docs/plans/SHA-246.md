# Implementation plan: SHA-246 Redacted console writer, error Display and panic hook

Ticket edits applied with this plan:

- No `Redactor` type (SHA-218 replaced it with the free function
  `rotate::redact::redact`). `Console::out()` and `Console::err()` return the
  SHA-218 `RedactingWriter`, which buffers what one statement writes and
  writes `redact` of it when dropped.
- The hidden subcommand is `__test-console <MODE>` with modes `out`, `error`,
  `panic` and `json`. It reads the canary from stdin as a `SecretValue`, so
  the value is registered exactly as a real secret is. It is compiled only
  with a new `test-commands` cargo feature. CI runs `--all-features`; the
  release workflow builds with no features, and a test without the feature
  proves the subcommand is unknown.
- AC5 is tested through the same print path `plan` uses (one string written
  through `console.out()`): `__test-console json` prints a JSON document
  whose string fields hold the canary. A real plan never holds a value, so
  `rotate --json plan --stdin` is also run and must parse as one document
  without the canary.
- From the SHA-194 review comment: every clap error goes through the
  console. Kinds that can echo a typed value never print it:
  `InvalidSubcommand`, `UnknownArgument` and `TooManyValues` keep the fixed
  "unrecognized argument" message, and `InvalidValue`, `ValueValidation`,
  `WrongNumberOfValues`, `InvalidUtf8` and `NoEquals` print "invalid value
  for '<arg>'" without the value. A config file that cannot be read is
  reported without its path. New T7 covers this.
- T4 runs clippy on a fixture crate from an integration test. The test job
  installs clippy and sets `ROTATE_REQUIRE_CLIPPY=1`, so the test fails in
  CI rather than skipping when clippy is missing. Locally it skips with a
  note when clippy is not installed.
- T6: the audit log does not exist yet (SHA-219). T6 greps every file the
  run leaves in the temp dir (where `--audit-log` and `--state-file` point),
  so it covers the audit file once it is written.

## Approach

`src/console.rs` (library) owns every byte the binary writes:

- `Console<O = Stdout, E = Stderr>` with `stdio()`, `new(out, err)`,
  `out()`, `err()` and `into_inner()`. `out()` and `err()` return
  `RedactingWriter<&mut O>`, used with `write!`/`writeln!`. One guard per
  message: nothing is written until the guard drops, so a value split
  across `write` calls is redacted whole.
- `report_parse_error(&mut self, &clap::Error, usage) -> i32` holds the
  fixed messages moved out of `main.rs` and returns clap's exit code. Help
  and version go to stdout, everything else to stderr, all redacted.
- `install_panic_hook()` replaces the default hook. It formats
  `thread '<name>' panicked at <location>:\n<payload>` into a zeroized
  buffer, redacts it and writes it to stderr with `write_all`. The process
  still unwinds out of `main`, so the exit code stays 101. A thread-local
  flag makes a second entry print a fixed line without formatting. In
  practice std already aborts on a panic inside the hook without calling it
  again and without printing the payload, so a panic in `redact` cannot
  recurse or leak.

`src/error.rs`: `rotate::error::Error` wraps any `std::error::Error + Send
+ Sync`. `Display` writes the message and its source chain joined by `: `,
redacted; `Debug` writes the same inside `Error(..)`. It does not implement
`std::error::Error` itself, so the blanket `From<E>` works (the anyhow
pattern).

`clippy.toml` disallows `std::print`, `std::println`, `std::eprint`,
`std::eprintln` and `std::dbg`. The console needs none of them, so no
`allow` is needed there. Test files that print add
`#![allow(clippy::disallowed_macros)]`.

Rejected: clippy's `print_stdout`/`print_stderr`/`dbg_macro` lints with
`allow-print-in-tests`. They must be enabled per crate target and the
"in tests" exemption misses helpers in `tests/common`. Rejected: a CI grep
for `println!`. It misses `std::println!` and macros re-exported under
another name, and it is not the lint the ticket names. Rejected: line
buffering in the console writer. It splits a multi-line value across two
`redact` passes; buffering per guard does not.

## Secret handling

The console never holds a value: it buffers text in `Zeroizing<Vec<u8>>`
(inside `RedactingWriter`) and writes only `redact` of it. The panic hook
formats into `Zeroizing<String>`. `Error` stores the source error unchanged
and redacts at format time, so a value registered after the error was built
is still caught. The test subcommand holds the canary as a `SecretValue`
and exposes it only to build the error, panic or JSON it is testing.

## Risks and unknowns

- SHA-250 is changing `plan` in `main.rs`. Whoever lands second merges and
  writes the plan string through `console.out()`.
- A value JSON-escaped as `\u00XX` (control characters) is not one of the
  registry's forms. Real tokens have no control characters.
- Dropping the value from clap value errors loses the parser's hint (for
  example the duration format). The message names the flag and `--help`
  documents the format.

## Out of scope

Log formatting (SHA-218), the audit log (SHA-219), plan content (SHA-250).
