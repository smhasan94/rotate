# Implementation plan: SHA-218 Redacting tracing layer

Ticket edits applied with this plan:

- The layer redacts the formatted line, not each field. Scope item (c) now
  reads: a `tracing_subscriber` fmt layer whose writer redacts each complete
  event before it reaches the sink. A `Layer` cannot change what other layers
  see, so redacting field by field would mean rewriting the formatter, and it
  would still miss span fields and `Debug` output of nested types. Redacting
  the whole line covers the message, every field and every span field.
- No `Redactor` type. The public API is a free function
  `rotate::redact::redact(&str) -> Cow<'_, str>` over a process-wide
  registry, so the audit log (SHA-219) and the console (SHA-246) call the same
  thing with no handle to pass around.
- Values shorter than 8 bytes, and values that are not valid UTF-8, are not
  registered. A short value would replace common words in every log line, and
  a non-UTF-8 value cannot appear in a `&str`. Real tokens are 20 bytes or
  more. Added to Scope.
- The registry also matches the `Debug`-escaped form of a value (what the fmt
  layer prints for a `&str` field holding `"` or `\`). Added to Scope next to
  URL-encoded and base64.
- AWS secret keys: a 40-character `[A-Za-z0-9/+]` run is redacted when an
  `AKIA`/`ASIA` key id or a secret-key keyword (`secret_access_key`,
  `SecretAccessKey`, `aws_secret`, any case) appears earlier in the same text,
  and the run is not all hex. "Following them" is made precise this way; the
  hex rule keeps git SHAs readable. `ASIA` ids are kept like `AKIA` ids.
- T7 runs as an integration test that re-executes the test binary as a child
  with the real stderr subscriber installed, and captures the child's stdout
  and stderr.
- AC6 is measured on `redact` itself over 10,000 pre-built 200-byte lines,
  so formatting cost is not counted. Wording updated.

## Approach

`src/redact/` has three parts.

1. `registry.rs`: a process-wide `Mutex<Inner>` holding one `Entry` per
   distinct value, keyed by its full SHA-256 and reference counted.
   `SecretValue` gets a `Registration` field. `Registration::new(bytes)`
   inserts or bumps the count; `Clone` bumps it; `Drop` decrements and removes
   the entry at zero. Clones of one value share one entry, so 1,000 copies of
   a finding cost one set of needles. An `Entry` holds the marker
   `[REDACTED sha256:<16 hex>]` and its forms in `Zeroizing<String>`: raw,
   `Debug`-escaped, percent-encoded (RFC 3986 unreserved kept, uppercase hex,
   as `urlencoding::encode`), base64 standard and URL-safe, each padded and
   unpadded. Forms shorter than 8 bytes or equal to another form are dropped.
   Every change bumps an `AtomicU64` generation.
2. `matcher`: built from a snapshot of the entries when the generation has
   moved, cached in a `RwLock<Option<Arc<Matcher>>>`. It indexes needles by
   their first two bytes, with a 65,536-bit bitmap for a fast reject, and
   lists candidates longest first. One left-to-right pass replaces the
   longest match at each position. The matcher holds `Arc<Entry>`, never a
   copy of a needle, so every copy of a value stays in zeroized memory.
   Redacting holds no lock while scanning.
3. `patterns.rs`: one `regex::Regex` for GitHub (`gh[pousr]_` + 36..255
   alphanumerics, `github_pat_` + 20 or more `[A-Za-z0-9_]`), npm (`npm_` +
   36), OpenAI (`\bsk-(proj-|svcacct-|admin-)?` + 20 or more `[A-Za-z0-9_-]`,
   containing a digit), giving `[REDACTED github|npm|openai]`; and the AWS
   rule above giving `[REDACTED aws]`.

`redact(text)` runs the registry pass, then the patterns, and returns
`Cow::Borrowed` when nothing matched.

`layer.rs`: `RedactingMakeWriter<M>` wraps any `MakeWriter`. Its writer
buffers the event in a `Zeroizing<Vec<u8>>` and on drop writes `redact` of the
buffer to the inner writer, so a value split across `write` calls is still
caught. `pub fn layer(level, make_writer)` returns the fmt layer (no ANSI,
filtered to `level`), `pub fn subscriber(level, make_writer)` a registry
with it, and `pub fn level_for(verbose: u8) -> LevelFilter` maps `-v`: 0 warn,
1 info, 2 debug, 3+ trace.

`main.rs` calls `tracing::subscriber::set_global_default(
redact::subscriber(redact::level_for(cli.global.verbose), std::io::stderr))`
right after parsing.

Rejected:
- `aho-corasick` or `regex` for registered values. Both copy the needles into
  their own memory, which is never wiped, so a dropped secret would stay in
  the heap. The bitmap scan is short and fast enough (see Risks).
- A `Layer` that rewrites field values through a visitor (see ticket edits).
- Storing only hashes of values and hashing every substring: needs a window
  per distinct length and still has to handle encoded forms.
- The `base64` and `urlencoding` crates in the library: the encoders are 30
  lines and write straight into zeroized buffers. Both crates are
  dev-dependencies so T3 checks against an independent encoder.

## Changes

- `Cargo.toml`: `regex = { version = "1", default-features = false, features
  = ["std", "perf", "unicode-perl"] }`; move `tracing-subscriber` from
  dev-dependencies to dependencies with features `fmt`, `std`, `registry`;
  dev-dependencies `base64 = "0.22"`, `urlencoding = "2"`. All MIT or
  Apache-2.0 (memchr and aho-corasick, pulled by regex, are MIT OR
  Unlicense).
- `src/redact/mod.rs`: `pub fn redact(text: &str) -> Cow<'_, str>`, the
  matcher, re-exports.
- `src/redact/registry.rs`: `pub(crate) struct Registration`, `Entry`,
  encoders, `MIN_LEN = 8`.
- `src/redact/patterns.rs`: provider regex and the AWS rule.
- `src/redact/layer.rs`: `RedactingMakeWriter`, `RedactingWriter`, `layer`,
  `subscriber`, `level_for`.
- `src/secret.rs`: `SecretValue` becomes `{ bytes: Zeroizing<Vec<u8>>,
  #[zeroize(skip)] registration: Option<Registration> }`; `new` and
  `from_reader` register; derived `Clone` clones the registration. Tests
  switch from `.0` to `.bytes`.
- `src/lib.rs`: `pub mod redact;`.
- `src/main.rs`: install the subscriber.
- `tests/redact_leak.rs`: T7.

## Secret handling

The registry keeps a copy of each live value and its encoded forms. All are
`Zeroizing` and wiped when the last `SecretValue` with that value drops and
the last matcher snapshot that references it is released. The registry key
is a SHA-256 digest, which the fingerprint already exposes a prefix of. The
writer buffer is zeroized. Not covered: the fmt layer's own thread-local
`String` buffer, which holds the unredacted line until it is reused (noted
for the memory-hardening ticket). Nothing in `redact` logs, so the writer
cannot recurse.

## Sequence

1. Registry, encoders, matcher, `redact` for registered values; T1 core, T3,
   registry extras.
2. `SecretValue` registration; existing secret tests green.
3. Provider patterns; T2 core, T5, pattern extras.
4. Writer, layer, `level_for`, `main.rs`; T1, T2, T4 through the layer.
5. T6, concurrency extra, T7; fmt, clippy, test, deny; PR.

## Risks and unknowns

- Debug builds: the bitmap scan and the regex run at opt-level 0 in
  `cargo test`. If T6 is close to the bound, add a literal prefilter (skip
  the regex unless the text holds `gh`, `npm_`, `sk-`, `AKIA`, `ASIA` or a
  keyword) before touching profiles.
- A value base64-encoded together with other bytes (HTTP Basic auth of
  `user:token`) is not caught; only provider patterns help there.
- Every `SecretValue` construction takes a global lock and hashes the value.
  That is microseconds per value and fine for report-sized input.
- Over-redaction by patterns is accepted: a marker in a log costs less than a
  leaked token.

## Out of scope

Console writer, error `Display` and panic hook (SHA-246), the audit log
(SHA-219), `RUST_LOG`-style filtering, JSON log output, memory locking.
