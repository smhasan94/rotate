# Implementation plan: SHA-217 SecretValue type

Ticket edits applied with this plan: AC2 and T2 reworded so the wipe is
observed on a live allocation (reading a freed buffer through a raw pointer
is undefined behaviour and proves nothing); T4 uses a `compile_fail` doctest
instead of `trybuild` (no compiler-version-specific stderr snapshot to
maintain); T6 asserts behaviour only, since a unit test cannot observe which
crate an `==` delegates to (review covers that); T7 spells out how stdout
and tracing are captured.

## Approach

First library code in the crate: `src/lib.rs` with `pub mod secret;`. The
binary keeps `cli` and `exit` as private modules for now; nothing in `main.rs`
uses the new type yet, so the binary is untouched apart from the lib target
appearing beside it.

`SecretValue` wraps `zeroize::Zeroizing<Vec<u8>>`. Bytes rather than `String`
because reports and stdin may carry non-UTF-8 material, and because every
provider ultimately sends bytes. `Debug` and `Display` both print
`SecretValue(sha256:…)`. There is no `Serialize` impl, so any struct that
derives `Serialize` with a `SecretValue` field fails to compile; that is the
guard against a secret reaching the audit log or state file by accident. A
hand-written `Deserialize` accepts a JSON string (or bytes) through a visitor
so no intermediate `String` outlives the call unzeroized. `PartialEq`
delegates to `subtle::ConstantTimeEq` on the byte slices. `Clone` is derived.

`Fingerprint` is a printable, `Serialize` and `Deserialize` newtype around the
`sha256:` plus 16 hex string from assumption A1. `SecretPair` holds an AWS
access key id (`String`, printable) next to a `SecretValue`; its fingerprint
is the secret half's.

Rejected: `secrecy` crate. It gives `ExposeSecret` and a `Debug` that prints
`[REDACTED]`, but the fingerprint in `Debug` is what makes rotate's logs
useful, and the custom `Deserialize` and constant-time `PartialEq` would be
wrappers anyway. Rejected: `Zeroizing<String>` as the buffer; it forces UTF-8
on input that is not always UTF-8 and gives no benefit over bytes. Rejected:
`Hash` impl; a hash that is consistent with constant-time equality would hash
the fingerprint, which is surprising. Callers that need a map key use
`fingerprint()`.

## Changes

- `Cargo.toml` deps: `zeroize` (features `alloc`, `derive`), `sha2`,
  `subtle`, `serde` (feature `derive`). Dev-deps: `serde_json`, `tracing`,
  `tracing-subscriber` (default features off, `fmt` only). All are MIT or
  Apache-2.0 or BSD-3-Clause; no `deny.toml` change.
- `src/lib.rs`: crate docs and `pub mod secret;`.
- `src/secret.rs`:
  - `pub struct SecretValue(Zeroizing<Vec<u8>>)` with
    `impl ZeroizeOnDrop`, derived `Clone`; constructors `new(impl Into<Vec<u8>>)`,
    `From<String>`, `From<Vec<u8>>`, `From<&str>`, and
    `from_reader(impl Read) -> io::Result<SecretValue>` which reserves a
    4 KiB buffer up front so a typical secret is read without a reallocation
    that would leave an unzeroized copy behind (documented limit, not
    enforced).
  - `expose_secret<R>(&self, f: impl FnOnce(&[u8]) -> R) -> R`,
    `expose_secret_str<R>(&self, f: impl FnOnce(&str) -> R) -> Result<R, Utf8Error>`
    (providers put tokens in headers), `len()`, `is_empty()`,
    `fingerprint() -> Fingerprint`.
  - `Debug` and `Display`: `SecretValue(<fingerprint>)`.
  - `Deserialize` via a visitor accepting `str`, `String`, bytes and byte
    buffers; owned inputs are moved, borrowed ones copied.
  - `PartialEq` and `Eq` via `subtle::ConstantTimeEq` on `&[u8]`; a length
    mismatch returns false after the comparison, which is what `ct_eq` on
    slices does.
  - `pub struct Fingerprint(String)`: `Fingerprint::of(&[u8])`, `as_str()`,
    `Display`, `Debug`, `Clone`, `PartialEq`, `Eq`, `Hash`, `Serialize`,
    `Deserialize`. Hex encoding is written by hand (8 bytes to 16 chars) to
    avoid a `hex` dependency.
  - `pub struct SecretPair { pub key_id: String, pub secret: SecretValue }`
    with `Debug` printing `SecretPair { key_id: "AKIA…", secret: SecretValue(sha256:…) }`,
    `fingerprint()` delegating to the secret, derived `Deserialize`, `Clone`,
    `PartialEq`.
- `CONTRIBUTING.md`: section "Handling secret values" (use `SecretValue`, never
  `String`; `expose_secret` only at the call that sends the bytes; never
  derive `Serialize` on a struct that holds one).

## Secret handling

The plaintext exists only inside the `Zeroizing` buffer and inside closures
passed to `expose_secret`. Both formatting impls and the `Debug` of
`SecretPair` go through `fingerprint()`. Deserialization moves owned strings
into the buffer; the borrowed-string path copies out of the deserializer's
input, which belongs to the report parser (SHA-223) to zeroize. `from_reader`
reads into a pre-reserved `Zeroizing<Vec<u8>>`; if the input exceeds the
reserve, `Vec` growth leaves an unzeroized copy, which is acceptable for MVP
and noted in the docs (mlock and allocator hardening are Later).

## Test mapping

All tests are unit tests in `src/secret.rs` unless stated.

- T1 (AC1): `debug_and_display_show_fingerprint_not_value`.
- T2 (AC2): `zeroize_wipes_whole_capacity` (build from a `Vec` with spare
  capacity, take pointer and capacity, call `Zeroize::zeroize` through the
  public impl, read the full capacity through the pointer while the value is
  still alive, assert all zero) and `secret_value_is_zeroize_on_drop` (a
  `fn assert<T: ZeroizeOnDrop>()` bound check).
- T3 (AC3): `fingerprint_known_answer_abc` (`sha256:ba7816bf8f01cfea`) and
  `fingerprint_is_stable_across_constructions`.
- T4 (AC4): `compile_fail` doctest on `SecretValue` calling
  `serde_json::to_string(&secret)`; the doctest runs in `cargo test` because
  `serde_json` is a dev-dependency.
- T5 (AC5): `deserializes_from_json_string_field` with `{"raw":"abc"}`.
- T6 (AC6): `eq_same_bytes`, `ne_different_length`,
  `ne_same_length_different_byte`, plus `ne_differs_only_in_last_byte` as a
  smoke check that the whole slice is compared.
- T7 (AC1, NFR7): `tests/secret_leak.rs` (integration, so it sees the crate
  as a downstream user would): format `SecretValue`, `SecretPair` and
  `Fingerprint` with `{}`, `{:?}` and `{:#?}` into an in-memory writer standing
  in for stdout; emit `tracing::info!(secret = ?value, secret_display = %value)`
  under a `tracing_subscriber::fmt` subscriber whose `MakeWriter` appends to a
  shared `Vec<u8>`; assert the plaintext appears in neither buffer and the
  fingerprint appears in both.
- Extra: `from_reader_reads_all_bytes`, `expose_secret_str_rejects_invalid_utf8`,
  `clone_is_equal_and_independent`, `secret_pair_debug_hides_secret`,
  `fingerprint_round_trips_through_serde`.

## Risks and unknowns

- Reading a `Vec`'s spare capacity through a raw pointer in T2 is sound only
  because `zeroize` writes every byte up to `capacity()` before `clear()`;
  the test comment says so and the assertion loops over `capacity`, not
  `len`, so a future change to `zeroize` that stops wiping spare capacity
  fails the test rather than reading uninitialized memory. If that assumption
  is wrong in the pinned `zeroize` version, fall back to a `Vec` with no spare
  capacity (`shrink_to_fit`) so only the initialized range is read.
- `sha2` 0.11 changed the output array type; `Fingerprint::of` indexes the
  digest as a slice so either 0.10 or 0.11 works.
- A `lib.rs` next to `main.rs` means doctests and `--all-targets` now build
  the lib twice; CI time impact is negligible at this size.

## Out of scope

Redaction of known values in logs (SHA-218), mlock and core-dump protection
(Later), trimming a trailing newline from stdin input (the stdin ticket).
