# Implementation plan: SHA-194 Crate skeleton with clap subcommand stubs

Ticket edits applied with this plan: AC1 reworded to use `RUSTFLAGS="-D warnings"`;
AC6 and T6 added for `--help` exiting 0.

## Approach

One binary crate `rotate` with clap derive. `main.rs` parses the CLI, maps the
chosen subcommand to a stub that prints "not implemented" on stderr and returns
exit code 2. `Option<Command>` with `None` treated as `plan` gives the "plan is
the default" behaviour. Exit codes live in one module from day one (0 ok,
1 rotation failure, 2 usage or config, 3 pending) so later tickets do not
invent their own.

Rejected: `args_conflicts_with_subcommands` with flattened plan args at top
level (lets `rotate report.json` work). Not needed until SHA-250 defines the
plan arguments; adding it now guesses at flags. Rejected: a lib plus bin split.
Single crate per conventions; `lib.rs` arrives in SHA-217 with the first
library type.

## Secret handling

No secret values in this ticket. `.gitignore` excludes `/.rotate/` so the
future audit log and state file are never committed by accident. No logging is
installed yet, so nothing can be printed except the fixed stub strings.
