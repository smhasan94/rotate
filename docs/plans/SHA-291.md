# Implementation plan: SHA-291 OpenAI scope widening

With an admin key, rotate's OpenAI replacement is a new service account with
the member role and all permissions: the Admin API neither shows a key's
permissions nor sets them on creation. A restricted leaked key would be
replaced by a broader one. From now on rotate does that only when the
operator opts in.

## Decisions

- Default (accepted in the ticket): without opt-in the OpenAI provider uses
  manual replacement mode (SHA-257 flow) even with an admin key. The admin
  key is still used for scope, for verify (the pasted key must be listed in
  the same project) and for revoke.
- Opt-in: `providers.openai.allow_broader_replacement: true` in
  `rotate.yaml`, or `--allow-broader-replacement` on `plan` and `apply`. The
  flag sets the config value for that run. With it the mode is Automatic.
- No blocker in either case. Without opt-in nothing widens (the operator
  pastes a restricted key), so the manual mode is the gate; with opt-in the
  operator accepted the widening. The ticket's "blocker unless opt-in" is
  replaced by the manual default.
- Provider trait: new pure method `scope_widening() -> Option<&'static str>`
  (default `None`). OpenAI returns `SCOPE_WIDENING_NOTE` whenever an admin
  key is configured: it says what an automatic replacement gets.
  - Automatic + note: the plan shows a `scope widening:` line under the
    replacement row, `replacement.scope_widening` in JSON holds the note, and
    the `create` audit entry records `scope_widened: true`.
  - Manual + note: the replacement row says the automatic replacement would
    get all permissions and names the opt-in; `scope_widening` is null.
- `PlannedRotation` gets `scope_widening: Option<&'static str>`.
- Plan JSON: new field `replacement.scope_widening` (string or null),
  documented in `docs/plan-schema.json`. Adding a field is compatible, so
  `version` stays 1.
- Audit: new optional field `scope_widened` (bool), written only on a
  `create` entry whose replacement widened scope. Older logs read unchanged.
- Manual instructions with an admin key name the project (name and id), the
  leaked key's name, and the keys page, and say to create a key with
  Restricted permissions matching the leaked key, in the same project.
