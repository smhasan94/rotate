# Implementation plan: SHA-269 user docs

## Sources of truth

Every command, flag, exit code, config key and environment variable in the
new docs is read from the code, not from memory:

- flags: the clap definitions in `src/cli.rs` (and `rotate <cmd> --help`);
- exit codes: the `Exit` enum in `src/exit.rs` and `apply::run_status`;
- config keys and defaults: the structs and `Default` impls in
  `src/config.rs`;
- environment variables: `config::ENV_*`, `audit::ENV_ACTOR`,
  `github::TOKEN_VARS`, `provider::npm::TOKEN_VARS`, the OpenAI
  `admin_key_env` default;
- name conventions: `plan::consumer_names`;
- audit and file-permission facts: `src/audit.rs`, `src/fsutil.rs`,
  `src/secret.rs`.

Provider-specific detail stays in `docs/providers.md` and
`docs/permissions.md`; the new docs link to them instead of repeating it.

## Docs

1. `docs/usage.md`: install, first run on a TruffleHog report, reading the
   plan, apply with typed confirmation, overlap window and re-run
   (`--overlap`, `--wait`), rollback, status, manual replacement, revoke by
   hand, every flag, exit codes.
2. `docs/config.md`: every `rotate.yaml` field with type, default and
   example; precedence (flag, env, file, default); environment variables;
   per-provider name conventions.
3. `docs/security.md`: the four guarantees verbatim from the brief, what
   the audit log holds, the fingerprint scheme, file permissions, the
   threat model summary, and a "Limits" section.
4. `docs/non-interactive.md`: `--confirm`, `--all`,
   `--replacement-from-env`, `--replacement-file`, `--json` (where it is
   supported and where it exits 2), exit codes, `ROTATE_ACTOR`, and an
   example GitHub Actions workflow that runs `rotate plan` on a schedule.
5. README: quick start rewritten against the real flow and linking all
   four; the exit code table moves to the docs (README links it).

## Tests (`tests/user_docs.rs`)

- T1 (AC1): runs `rotate --help` and `rotate <cmd> --help` for every
  visible subcommand, extracts every `--flag`, and asserts each is named in
  `docs/usage.md` or `docs/non-interactive.md`. Also asserts every `Exit`
  code in `src/exit.rs` has a row in the exit code tables of both docs.
- T2 (AC2): a YAML block in `docs/config.md` sets every field. The test
  parses it as a `FileConfig` and destructures every config struct with no
  `..`, so a new field fails to compile until the test (and the doc) name
  it; each field's dotted key must appear in the doc as a heading followed
  by a `Default:` line.
- T3 (AC3): extracts the fenced `sh` blocks marked `<!-- test: <scenario>
  -->` from `docs/usage.md` and runs each command, in order per scenario,
  against the acceptance-test wiremock models (`tests/e2e`), with the
  `rotate.yaml` block from the doc plus the mock endpoints. `# exit N`
  and `# expect: <text>` comments set the expected exit code and output.
- T4 (AC4): `docs/security.md` holds the four guarantee sentences verbatim
  and a "Limits" heading with at least three bullets.
