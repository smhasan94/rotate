# Implementation plan: SHA-290 rollback exits 1 when the old secret stays revoked

`rotate rollback` of a `revoked` rotation whose old secret cannot be
reactivated restores the consumers, revokes the replacement and exits 0
with a `warning:` on stderr. Every restored consumer then holds a dead
credential and nothing live exists: an outage that a CI caller reads as
success. The actions stay as they are (that design question is out of
scope); the outcome, exit code, summary and plan text change so nobody
mistakes it for a clean rollback.

The two paths in `src/rollback.rs` are as the ticket describes:
`RollbackExecutor::steps` calls `unsupported_old` for
`OldSecretAction::Restore(handle)` when `provider.restore` returns
`RestoreOutcome::Unsupported`, and for `OldSecretAction::Unsupported`
(step `revoked`, no `restore_ref`). Today only the mock reaches the first
(AWS, the one provider that gives a handle, restores it). The second is
reached by GitHub, npm and OpenAI (`revoke` returns `restore_ref: None`),
by AWS when the key was already deleted (`src/provider/aws.rs` `revoke`,
"no such slot"), and by a rotation apply recorded `revoked` after a
revoke by hand (SHA-289, `Executor::confirm_revoked_by_hand`): there the
old secret is gone for good, so exit 1 is right for it too.

## Decisions

- One new variant, `RollbackResult::RolledBackOldRevoked { reason: String,
  holding: Vec<String> }`. `reason` is rotate's own text (`"<provider>
  cannot reactivate a revoked credential"` or `"the provider gave no
  handle to reactivate it"`), never upstream text, so a plain `String` is
  fine. `holding` is the refs of every consumer whose saved status is
  `restored` when the rollback finishes, which includes consumers restored
  by an earlier, interrupted run. The rotation still ends at `rolled_back`
  with `restore_done` and `revoke_done` true, so a re-run has no work and
  makes no call, as today.
- The warning moves out of `RollbackOutcome::warnings` and into the
  variant. `unsupported_old` stops pushing to `progress.warnings` and sets
  `progress.old_revoked = Some(reason)`; `steps` returns the new variant at
  the end when it is set. The stderr line keeps its exact text
  (`the old secret was not reactivated (<reason>); it stays revoked, so the
  restored consumers hold a revoked secret`), produced by
  `RollbackOutcome::stderr_warnings()`, which yields that line first and
  then `warnings`. Without this move, `render_summary` would print the
  generic `warning:` note and the new line for the same rotation.
- A resumed rollback must end the same way. Today an interrupted rollback
  that already recorded the skipped `restore_old` resumes with
  `OldSecretAction::Done` and would exit 0, although the old secret is
  revoked. `RollbackProgress` (`src/state.rs`) gains
  `old_still_revoked: bool` with `#[serde(default, skip_serializing_if =
  "is_false")]` (a two-line helper next to the struct). It is written only
  when true, so every existing file and every assertion on
  `{"restore_done": .., "revoke_done": ..}` is unchanged, and older files
  load as before (`deny_unknown_fields` stays). State schema stays
  version 1. The ticket does not mention this; it is needed for AC1 and AC2
  to hold across the re-run the rollback docs promise.
- The summary header always shows the new count, as apply's header shows
  every count: `Rollback: {n} rolled back, {m} with the old secret still
  revoked, {f} failed.` The `# expect:` line in `docs/usage.md` section 6
  and the assertion in `tests/rollback_cli.rs` change with it.
- `any_failed` is renamed `needs_operator` and returns true for `Failed`
  and the new variant; `main.rs` maps true to `Exit::RotationFailed`. No
  new exit code: 1 already means "stop and page a human".
- `rotate status` says it in the hint only: at `rolled_back` with
  `old_still_revoked`, the hint becomes `rolled back; the old secret stays
  revoked: create a new credential and run \`rotate apply\``. The row
  stays not pending and hidden without `--all`; no field is added to
  `docs/status-schema.json`, whose `hint` is free text. Cheap, and the only
  place the fact survives once the terminal output is gone.
- Audit log unchanged: the skipped `restore_old` entry already carries the
  reason.

## Maintainer decisions (2026-10-04)

These settle the open questions and override the plan where they differ.

- Resume gap: in scope. Add `RollbackProgress.old_still_revoked` (written
  only when true; state schema stays version 1) and
  `OldSecretAction::StillRevoked`, so a rollback interrupted after the
  skipped `restore_old` also exits 1 when it finishes.
- Header: the third count is always shown, like apply's header:
  `Rollback: {n} rolled back, {m} with the old secret still revoked, {f} failed.`
- `rotate status`: keep the hint at `rolled_back` when the flag is set (no
  status-schema change).
- Rename `any_failed` to `needs_operator`.

## Changes

`src/rollback.rs`:

- `OldSecretAction::StillRevoked`: `RollbackPlan::of` returns it when
  `progress.restore_done && progress.old_still_revoked`, before the `Done`
  case. `has_work` treats it like `Done` (the resume flag carries the
  work). `render_plan` prints `stays revoked: an earlier run could not
  reactivate it; the restored consumers hold a revoked secret and rollback
  exits 1`.
- `UNSUPPORTED_TEXT` becomes `unsupported: old secret cannot be
  reactivated; consumers will be restored but left holding a revoked
  secret, and rollback will exit 1`. Same constant name: existing tests
  reference it.
- `Progress` gains `old_revoked: Option<String>`. `unsupported_old(progress,
  reason)` sets it, sets `restore_done` and `old_still_revoked` on
  `progress.rollback()`, saves, and appends the skipped `restore_old` event
  as today; it no longer pushes a warning. The `StillRevoked` arm of
  `steps` sets `restore_done`, `old_still_revoked` and
  `old_revoked = Some("an earlier rollback run could not reactivate it")`
  and saves, with no new audit event (the first run recorded it).
- End of `steps`: after the final `rolled_back` save and event, return
  `RolledBackOldRevoked { reason, holding }` when `progress.old_revoked` is
  set, where `holding` is the `restored` refs of `progress.record.consumers`;
  otherwise `RolledBack`. The record-failure branch is unchanged.
- `RollbackOutcome::stderr_warnings(&self) -> Vec<String>` and
  `pub fn old_revoked_warning(reason: &str) -> String` (today's text).
- `needs_operator(outcomes) -> bool` replaces `any_failed`.
- `render_summary`: header as decided; the row's last column reads
  `rolled back, old secret still revoked`; one note per such rotation:
  `<id>: <provider>: the old secret stays revoked (<reason>); <refs> now
  hold a revoked secret; create a new credential and run rotate apply
  again`, with `no consumer holds it` when `holding` is empty. Failure
  notes and generic warning notes are unchanged.

`src/state.rs`: the `RollbackProgress` field and helper; doc comment says
when it is set.

`src/status.rs`: `hint` at `Step::RolledBack` checks
`rotation.rollback.as_ref().is_some_and(|p| p.old_still_revoked)`.

`src/main.rs` `rollback`: iterate `outcome.stderr_warnings()` instead of
`outcome.warnings`; `if rollback::needs_operator(&outcomes)`.

`src/exit.rs`: the `RotationFailed` doc comment adds "or `rollback`
finished with the restored consumers holding a revoked secret".

Docs (`tests/user_docs.rs` T1 checks that rows `| 0 |` to `| 4 |` and
`| 101 |` exist in both exit tables and that every `--help` flag is named;
no flag or code is added, so only the text changes):

- `docs/usage.md` section 6: the bullet "When the provider cannot bring
  the old secret back" says consumers are restored but hold a revoked
  secret, rollback exits 1, and the fix is a new credential and `rotate
  apply`; the `# expect:` header line in the `overlap` scenario (that
  rollback is at `pending_revoke`, so it stays `1 rolled back, 0 with the
  old secret still revoked, 0 failed.`); section 9 row 1 adds the rollback
  case.
- `docs/non-interactive.md` exit table row 1: the meaning and "what a
  script should do" (`rotate status --all` shows the hint; create a new
  credential and run `rotate apply`).
- `README.md` rollback bullet: same sentence as usage.md.
- `docs/providers.md`: the three `restore` rows that say "Rollback restores
  consumers only" (GitHub, npm, OpenAI) and the note under the matrix add
  "and exits 1".
- `CHANGELOG.md` under `[Unreleased]`, `### Changed`.

## After merge

None. The design question the ticket defers (refuse such a rollback, or
skip the consumer restore and the replacement revoke) stays open; this
change makes the outcome visible without changing what is done.
