# Implementation plan: SHA-219 Append-only JSONL audit log

Ticket edits applied with this plan:

- AC2 and T2: no command writes the audit log yet (apply is SHA-254), so
  there is no CLI path that can exit 2. AC2 now says opening a 0644 log
  returns `AuditError::WideMode` naming the file and the expected mode 0600,
  writes nothing, and `AuditError::is_usage()` is true for it, which is the
  contract the CLI maps to exit 2. The CLI exit-code check moves to SHA-254,
  the first command that opens the log. This mirrors SHA-220 AC4.
- T5: the child process is this test binary re-run with an env var, as in
  SHA-220's lock test. The parent kills it with SIGKILL after a varying
  number of lines (1 to 99, picked from the clock).
- T6: the env var is set on a child process rather than with
  `std::env::set_var` in the test process, because other tests in the same
  binary read the environment concurrently. A unit test covers the
  resolution rules through an injected lookup.
- The `step` enum is `AuditStep` in code (JSON values unchanged) so it does
  not clash with `state::Step` where SHA-254 imports both.
- A final line without a trailing newline (a write cut short) is skipped by
  `read_all()`, and the next `open` for appending terminates it with a
  newline so the next entry starts on its own line. That fragment then reads
  back as a corrupt line, reported by line number.

## Approach

One module, `src/audit.rs`, on top of `fsutil` (SHA-220).

Types. The caller builds an `AuditEvent` (rotation id, provider,
fingerprint, optional replacement fingerprint, optional consumer, step,
outcome, optional error) and passes it to `AuditLog::append`, which stamps
`version`, `ts` and `actor` and writes an `AuditEntry`. `AuditEntry` is also
what `read_all()` yields. Both hold `Fingerprint`s only: `SecretValue` has no
`Serialize`, so a field of that type would not compile, and the fingerprint
fields are typed `Fingerprint`, so a `SecretValue` cannot be passed where one
is expected. A `compile_fail` doctest proves it.

Redacted errors. `error` is `Option<RedactedText>`. `RedactedText` has a
private `String` and one constructor, `RedactedText::new(&str)`, which runs
`redact::redact` (SHA-218). Its `Deserialize` impl redacts too, so even a
hand-edited log read back is redacted. A caller cannot store raw text.

Open and append. `AuditLog::open(path)` calls
`fsutil::open_private(path, append + create + read)`: parent directories get
mode 0700, a new file gets 0600, an existing file with any group or other
bit, a symlink or a non-regular file is refused and nothing is written.
`append` serializes the entry with `serde_json`, adds `\n`, and writes the
whole line with one `write_all` on the `O_APPEND` descriptor, then
`sync_data`. A crash leaves either no line or a whole one in practice; the
reader still copes with a fragment (above).

Timestamps. `ts` is RFC 3339 UTC through `time::serde::rfc3339`, as in
`state.rs`. `open` reads the existing entries once and remembers the latest
`ts`; `append` uses `max(now, latest)`, so `ts` never goes backwards in the
file even if the wall clock steps back. Non-decreasing, not strictly
increasing: two entries in one clock tick share a `ts`; line order is the
order of events.

Schema version. Each line carries `"version": 1` (`AUDIT_VERSION`). Lines
with a higher version are reported as `AuditError::NewerVersion` by line
number. Unknown fields are rejected, like the state file.

Actor. `ROTATE_ACTOR` if set and non-empty, else `user@hostname`. User from
`$USER`, then `$LOGNAME`, else `unknown`. Hostname from
`/proc/sys/kernel/hostname` (Linux), else the output of `/bin/hostname`
(macOS, absolute path so `PATH` cannot substitute it), else `unknown`.
Resolved once per `open`. No new dependency: `gethostname(2)` through
`libc` needs `unsafe`, which the crate denies, and the `gethostname` or
`whoami` crates add a dependency for one string. The actor is informational,
not an authentication claim; the env vars it reads are under the operator's
control anyway.

`read_all(path)` returns an iterator of `Result<AuditEntry, AuditError>`,
one item per complete line, for `status` (SHA-263) and idempotency checks
(SHA-254). A missing file gives an empty iterator. A bad line gives
`AuditError::Corrupt { path, line, reason }` with the serde position only,
never the line's text, and iteration continues. A final line without `\n`
is skipped. It opens through `open_private` read-only, so a wide file is
refused for reading too.

Concurrency: appends from two processes are separate `O_APPEND` writes of
whole lines; the state lock (SHA-220) already keeps two `apply` runs apart,
so the log takes no lock of its own.

Rejected: rewriting the file through `write_atomic` per entry (not
append-only, slow as the log grows); truncating a partial last line on open
(an audit log should never lose bytes, even broken ones); a line-level
`redact` over the whole serialized entry (could change JSON escapes; the
other fields are identifiers, not values); `chrono` (same reasons as
SHA-220).

## Secret handling

The log holds fingerprints, provider names, rotation ids and consumer refs
(public identifiers such as `org/repo:NAME`). The only free text is `error`,
which can only be built through `redact`. Every live `SecretValue` is in the
SHA-218 registry, so a value in an error string becomes
`[REDACTED sha256:...]`, and provider-shaped tokens are caught even when not
registered. Error messages name paths, line numbers and modes, never line
contents. Tracing at debug level logs rotation id, step, outcome and
fingerprint only.

## Risks and unknowns

- `write_all` on a regular file is one `write(2)` in practice, but POSIX
  does not promise it. A fragment is handled by the reader and by `open`.
- `/bin/hostname` is spawned once per `open`. If it is missing the actor
  says `unknown` for the host; that is acceptable for an informational field.
- `read_all` reads the whole file at `open` to find the latest `ts`. Logs
  are small (a few lines per rotation); a tail read can replace it later.

## Out of scope

Calling the log from commands (SHA-254 apply, SHA-263 status, SHA-259
rollback), the CLI exit-code mapping, log rotation or remote shipping,
Windows.
