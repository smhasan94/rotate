# Implementation plan: SHA-248 Assessment: identify, dedupe, check validity

Ticket edits applied with this plan:

- Findings with the same fingerprint are merged into one, keeping every
  source. The credential is taken from the finding that carries an
  `access_key_id` when there is one, otherwise the first. A gitleaks
  `generic-api-key` finding and a TruffleHog `AWS` finding for the same key
  share a fingerprint and become one AWS rotation with the key id.
- Besides Supported and Unsupported there is a third disposition,
  `NotRotatable { reason }`. This is the SHA-223 note on gitleaks
  `aws-access-token` findings, which hold only a key id: they are never sent
  to `check_valid`, and the reason points at TruffleHog or
  `--stdin KEY_ID:SECRET`. A canary key (`extra.is_canary`) is also
  `NotRotatable`, so that it is never sent to AWS (note on SHA-251).
- Retry: 3 attempts in total, only on `ProviderError::is_retryable()` (429
  and transient). The backoff is `base * 2^n`, or the provider's
  `retry_after` when it gives one. The base delay is an option (default
  500 ms) so that tests run in milliseconds.
- `describe_scope` runs after a Valid check, inside the same semaphore permit
  and with the same retry. A scope failure leaves `scope = None` with a
  reason; it does not change validity.
- `MockProvider` gains `.latency(Duration)` and in-flight tracking
  (`max_in_flight()`), which T3 needs and SHA-249 can reuse.
- The CLI half (`plan` printing the assessment table or `--json`, and
  `--concurrency N`) is built on top of SHA-247, which owns input. The
  library half does not depend on it.

## Approach

`src/assess.rs`:

- `pub struct AssessOptions { concurrency: usize (default 8), attempts: u32 (3), base_delay: Duration (500 ms) }`.
- `pub enum Disposition { Supported { provider: &'static str, confidence }, Unsupported, NotRotatable { reason } }`.
- `pub struct Assessed { fingerprint, credential: Credential, disposition, validity: Option<Validity>, scope: Option<Scope>, scope_error: Option<String>, detectors: Vec<String>, sources: Vec<SourceLocation> }`. It holds the credential, because the plan and apply stages need it, and so it has no `Serialize`.
- `pub async fn assess(findings: Vec<Finding>, registry: &ProviderRegistry, opts: &AssessOptions) -> Vec<Assessed>`, in first-seen order:
  1. Group by fingerprint (an ordered map), merging sources and detectors.
  2. Identify each group: the hint table maps the detector to a provider name (TruffleHog `AWS`, `Github`, `GitHubOauth2`, `NpmToken`, `NpmTokenV2`, `OpenAI`, `OpenAIAdminKey`; gitleaks `github-pat`, `github-fine-grained-pat`, `github-oauth`, `github-app-token`, `npm-access-token`, `openai-api-key`; `aws-access-token` is `NotRotatable`). If the named provider is registered, it wins. If the registry's pattern match (`registry.identify`) names a different provider, a `tracing::warn!` names both (AC7). With no hint, or a hint for an unregistered provider, the pattern match decides; nothing, or an ambiguous tie, is `Unsupported` (ambiguity gives a reason).
  3. Check Supported groups concurrently under a `tokio::sync::Semaphore` through a `JoinSet`: `check_valid` with retry, then `describe_scope` if Valid. A final error becomes `Validity::Unknown { reason: err.to_string() }`.
- Rendering, shared with `plan` (SHA-250):
  - `pub fn render_table(&[Assessed]) -> String`: columns provider, fingerprint, status (`valid`, `invalid`, `unknown: reason`, `unsupported`, `not rotatable: reason`), sources (first, `+N more`), and the scope identity when known.
  - `pub fn render_json(&[Assessed]) -> String`: an array of `{provider, fingerprint, status, reason, detectors, sources: ["file:line@commit"], scope: {identity, lines}}` through a `Serialize` view struct, never through `Assessed`.

Rejected: `futures::join_all`, which would add a dependency; `JoinSet` is in
tokio. Rejected: checking every finding before deduping, which would call
the provider once per copy.

## Changes

- `Cargo.toml`: `tokio = { version = "1", features = ["sync", "time", "rt", "macros"] }` moves to dependencies (dev keeps `rt-multi-thread`); `serde_json` is already a dependency.
- `src/assess.rs`, `src/lib.rs` (`pub mod assess;`).
- `src/provider/mock.rs`: `latency`, `max_in_flight`, `in_flight` guard.
- CLI half: `--concurrency` on `plan`, and `plan` printing `render_table` or `render_json` in place of the SHA-247 findings summary. Exit 0 when nothing failed to parse; unsupported rows do not change the exit code (AC2).
- `docs/`: assessment statuses in the `--help` text; `docs/report-formats.md` gets a short "what happens next" note on dedupe.

## Test mapping

Unit tests are in `src/assess.rs`, using `#[tokio::test]`. Every test shares one `CallLog` and ends with `log.assert_no_mutations()` (T6).

- T1 (AC1): `same_secret_three_files_is_one_assessment`.
- T2 (AC2): `unknown_finding_is_unsupported` (library), plus CLI `tests/assess_cli.rs::unsupported_row_exits_0` with `--all-features` mocks.
- T3 (AC3): `concurrency_is_bounded`: 20 findings, latency 100 ms, concurrency 4; `max_in_flight() <= 4` and elapsed under 1 s.
- T4 (AC4): `retries_rate_limit_then_valid`: `fail_next` 429 twice; Valid; three `check_valid` calls.
- T5 (AC5): `persistent_failure_is_unknown_others_continue`.
- T6 (AC6): the shared-log assertion in every test.
- T7 (AC7): `hint_beats_pattern_and_warns` under `LogCapture`.
- T8 (all): `tests/assess_leak.rs`: a canary through every path (valid, invalid, unknown with an error, unsupported, not rotatable, deduped); absent from `render_table`, `render_json`, `Debug` and tracing. The CLI half adds stdout and stderr of `plan --json`.
- Extras: `gitleaks_aws_key_id_is_not_rotatable_and_not_checked`, `canary_is_not_rotatable_and_not_checked`, `dedupe_prefers_finding_with_key_id`, `ambiguous_pattern_is_unsupported_with_reason`, `scope_failure_keeps_validity`, `retry_honours_retry_after`, `non_retryable_error_is_not_retried`, `json_schema_fields_stable`.

## Secret handling

`Assessed` holds the credential but has no `Serialize`; JSON goes through a
view with fingerprints only. `Validity::Unknown` reasons and `scope_error`
come from `ProviderError` `Display`, which providers must keep value-free
(the CONTRIBUTING rule). The redaction layer (SHA-218) is the backstop.
Warnings name providers and detectors, never values.

## Sequence

1. Mock latency and in-flight tracking.
2. Grouping and identification; T1, T2, T7 and the identification extras.
3. Concurrent checking with retry; T3, T4, T5 and the retry extras.
4. Renderers and T8 (library).
5. On top of SHA-247: CLI wiring, `--concurrency`, CLI tests; fmt, clippy, test, deny; PR.

## Out of scope

The plan itself and consumer lookup (SHA-250), real providers (SHA-251,
SHA-260 to SHA-262), the conformance suite (SHA-249).
