# Implementation plan: SHA-287 https-only endpoints, plan warns on non-default ones

`ApiUrl` (`src/config.rs`) accepts `http://` to any host, so a tampered
`rotate.yaml` can send a new secret or an operator token in clear text to a
host someone else controls. It backs `providers.github.api_url`,
`providers.npm.registry`, `providers.openai.api_url` and
`providers.aws.endpoint_url`, and through `src/providers.rs` every real
provider and both consumers (`GithubActionsConsumer::from_config` takes
`GithubConfig`; `secrets_manager` takes `AwsConfig`). Nothing else reads an
endpoint: `Overrides` has no URL field, no environment variable names one,
and the test scenario (`ROTATE_TEST_SCENARIO`) carries no URL. The plan
does not show which endpoints are in use.

The ticket's description of the code still holds; the only drift is in the
tests and docs it would break, listed under Changes.

## Decisions

- Parse with the `url` crate instead of extending the hand-written prefix
  check. The ticket's confusion cases (`http://127.0.0.1.evil.example`,
  `http://localhost@evil.example`, `http://evil.example/127.0.0.1`) are
  exactly what ad hoc host extraction gets wrong. `url` 2.5 is already in
  the tree through reqwest 0.12 (which re-exports it as `reqwest::Url`); it
  becomes a direct dependency, `url = "2"`, with the "already in the tree"
  comment the manifest uses for rustix and aws-credential-types. MIT OR
  Apache-2.0, so `deny.toml` is unchanged.
- Loopback means `Ipv4Addr::is_loopback`, `Ipv6Addr::is_loopback` or the
  domain `localhost`. That is the ticket's three hosts plus the rest of
  127/8, which never leaves the machine either. `Url` lowercases scheme and
  host, so the comparison is case-insensitive for free.
- A URL with userinfo is refused before any other check, and its error
  shows nothing of the URL. Every other `InvalidUrl` shows at most the
  parsed scheme and host (`http://api.example.com`), never the written
  text: the current message echoes the whole value (`invalid URL
  {0:?}`), which is what would leak a password. The field name is not part
  of the message: `ConfigError::Invalid` already prints it from
  `serde_path_to_error` (`rotate.yaml: providers.npm.registry at line 3,
  column 15: ...`), and T1 asserts on that `field`.
- The warnings are plan data, not a stderr side channel: `Plan.warnings`,
  rendered on stdout right after the header line and carried in `--json`
  as a top-level `warnings` array. Apply prints them through
  `render_apply_table`, which `main::apply` already prints before
  `apply::confirm`. They go after the header, not before it:
  `tests/apply_safety.rs::apply_header_is_not_dry_run` asserts stdout
  `starts_with("Plan to apply: ...")`.
- "Differs from the default" compares the parsed URLs with a trailing `/`
  trimmed, so `https://api.github.com/` and `HTTPS://API.GITHUB.COM` do not
  warn (the provider constructors already trim the slash, see
  `providers::tests::openai_settings_come_from_config`). Any
  `providers.aws.endpoint_url`, loopback included, warns: the default is
  AWS's own endpoints.
- `ApiUrl::as_str` keeps returning the text as written. Providers trim and
  join it themselves today; normalising it would change `web_url` and the
  `Debug` output tests in `src/providers.rs` for no gain.
- `rotate.yaml` is the only input for these fields, so the rule lives in
  `TryFrom<String> for ApiUrl` and nothing else needs to call it. The
  `ApiUrl` doc comment says that any later endpoint field or override must
  use the type.

## Maintainer decisions (2026-10-04)

These settle the open questions and override the plan where they differ.

- Loopback is any `127.0.0.0/8` address, `::1` or `localhost`
  (`is_loopback()`), not only the ticket's three hosts: the whole range
  cannot leave the machine.
- A loopback `providers.aws.endpoint_url` (LocalStack) still warns: any
  override changes where secrets go.
- Wording as proposed: `providers.npm.registry is https://npm.example.com
  (default https://registry.npmjs.org)` and `providers.aws.endpoint_url is
  <url> (default: AWS's own endpoints)`.
- `--json` always emits `warnings` (an empty array when there are none);
  `docs/plan-schema.json` lists it as an optional property, so the change
  stays additive and the version stays 1.

## Changes

- `Cargo.toml`: `url = "2"` under `[dependencies]`.
- `src/config.rs`:
  - `pub const DEFAULT_GITHUB_API_URL`, `DEFAULT_NPM_REGISTRY`,
    `DEFAULT_OPENAI_API_URL`; the three `Default` impls use them.
  - `InvalidUrl` becomes an enum: `NotAUrl` ("expected
    https://host[:port][/path]"), `Scheme { scheme }`, `Userinfo` ("must not
    carry a user name or password"), `NotHttps { origin }` ("`<origin>` is
    neither https nor loopback: only https:// is accepted, except http://
    to 127.0.0.1, ::1 or localhost"). `origin` is `scheme://host[:port]`
    from the parsed URL. No variant holds the written string.
  - `TryFrom<String> for ApiUrl`: `Url::parse`; refuse `cannot_be_a_base`
    and a missing host; refuse a non-empty `username()` or `password()`;
    accept scheme `https`; accept `http` only when `host()` is
    `Host::Ipv4` or `Host::Ipv6` with `is_loopback()` or
    `Host::Domain("localhost")`. Store the written string.
  - `impl ProvidersConfig { pub fn endpoint_warnings(&self) -> Vec<String> }`
    in field order aws, github, npm, openai:
    `providers.aws.endpoint_url is http://127.0.0.1:4566 (default: AWS's own endpoints)`,
    `providers.npm.registry is https://npm.example.com (default https://registry.npmjs.org)`.
    A private `ApiUrl::normalized()` (re-parse, trim the trailing `/`) does
    the comparison.
  - `ApiUrl` doc comment states the rule and that every endpoint setting
    must use the type.
- `src/plan.rs`: `Plan.warnings: Vec<String>` (set to `Vec::new()` in
  `build`; `Plan` has no other literal outside `build`). `render_at` writes
  `warning: <text>` per entry after the header line. `PlanView.warnings:
  &[String]`, filled by `render_json`. Always emitted, empty array when
  nothing is configured.
- `src/main.rs` `build_plan`: `plan.warnings =
  config.providers.endpoint_warnings();` after `plan::build`, so `plan` and
  `apply` share it.
- `docs/plan-schema.json`: `warnings` (`array` of `string`) under
  `properties`, not `required`; `version` stays 1, as `recorded` did in
  SHA-294. `tests/plan_cli.rs::json_validates_against_schema_and_has_no_value`
  fails until this is done (`additionalProperties: false`).
- `docs/config.md`: a `## Endpoint URLs` section before `## Fields` with
  the rule, the loopback exception and the plan warning; the four URL
  sections keep their `Type:` and `Default:` lines (`tests/user_docs.rs`
  T2 needs both) and `providers.aws.endpoint_url` loses "(`https://` or
  `http://`)". Its complete example uses `http://localhost:4566`, which
  stays valid.
- `docs/rotate.example.yaml`: one comment under `providers:` with the
  rule. `config::tests::example_config_parses` is unchanged.
- `docs/usage.md` section 3 (plan output): a bullet for the endpoint
  warning. `docs/non-interactive.md` table row for `rotate plan`: add
  `warnings`.
- `CHANGELOG.md` Unreleased: a `### Security` entry.
- `CLAUDE.md`: no change; the brief does not list config rules.

Nothing in the tree outside `.claude/worktrees` uses a non-loopback
`http://` URL or a URL with userinfo: `tests/fixtures/config/full.yaml`,
`docs/config.md`, `docs/rotate.example.yaml`, `tests/e2e/mod.rs`,
`tests/status_cli.rs`, `tests/npm_operator.rs`, `tests/openai_provider.rs`
and `tests/user_docs.rs::config_for` all point at wiremock on
`http://127.0.0.1:<port>`, which stays accepted. Those runs now print one
to four warning lines in every plan; they assert with `contains` and the
usage guide's `# expect:` lines, not whole-output equality, so nothing
there changes. `config::tests::api_url_must_be_http_or_https` becomes T1
to T3 below.

## Tests

- T1 `config::tests::sha287_t1_non_loopback_http_names_its_field` (AC1,
  AC4): `http://api.example.com` in each of the four fields through
  `invalid(...)`; `field` is the dotted path, the message contains
  `https` and `localhost`, and the full `Display` starts with
  `rotate.yaml: providers.github.api_url at line`. Integration half
  `tests/config.rs::sha287_t1_http_endpoint_exits_2_before_anything`: a
  `rotate.yaml` with the bad GitHub URL; `plan`, `apply`, `rollback` and
  `status` exit 2 with stderr naming the field, and no `.rotate/`
  directory exists afterwards (`StateStore::open` would have created it).
  "No provider is built" is structural: `Config::load` runs in `main`
  before `providers::registry_with`.
- T2 `config::tests::sha287_t2_loopback_http_is_accepted` (AC2):
  `http://127.0.0.1:4566`, `http://[::1]:8080`, `http://localhost:4873`,
  `http://LOCALHOST:4873`, `HTTP://127.0.0.1`, `http://127.0.0.1:4566/`
  in each field; `as_str()` is the written text.
- T3 `config::tests::sha287_t3_host_confusion_and_userinfo_are_refused`
  (AC3): `http://127.0.0.1.evil.example`, `http://localhost@evil.example`,
  `http://evil.example/127.0.0.1`, `https://user:pass@api.example.com`,
  `http://user@localhost`, `ftp://x`, `https://`, `api.github.com`; each
  refused, and no message contains `pass`, `user` or `@`.
- T4 `tests/plan_cli.rs::sha287_t4_custom_registry_warns_once_in_table_and_json`
  (AC5): `rotate.yaml` in the `Run` dir with
  `providers.npm.registry: https://npm.example.com` (the mocks ignore it;
  the warning comes from the config). Exactly one stdout line starts with
  `warning:` and it names the field and the URL, between the header and
  the first `Rotation` line; `--json` has `warnings == [that text]` and
  validates against the schema.
- T5 `tests/plan_cli.rs::sha287_t5_default_endpoints_warn_nothing` (AC6):
  no `rotate.yaml`, then one spelling every default out with a trailing
  `/`; no `warning:` line and `warnings == []`.
- T6 `tests/apply_cli.rs::sha287_t6_apply_warns_before_the_question`
  (AC7): a `run_merged` helper spawns the binary with stdout and stderr as
  two `Stdio::from` handles of one append-mode file, so the two streams
  land in write order (the plan ends in a newline, so `Stdout`'s line
  buffer is flushed before the question; the question goes to stderr
  through `QuestionWriter`). With the T4 config and `prompt: {answers:
  [id]}`, the warning's offset is below `Type the rotation id`'s, and the
  rotation completes.
- T7 `tests/plan_cli.rs::sha287_t7_custom_endpoints_add_no_call` (AC5,
  AC7): all four fields non-default (`https://` hosts and a loopback
  `endpoint_url`), four warnings, and the call log holds only `identify`,
  `check_valid`, `describe_scope` and `find`, none `mutating`, as
  `plan_makes_no_mutating_calls` checks.
- T8 `tests/leakage.rs::sha287_t8_userinfo_canary_stays_out_of_every_output`
  (AC3): for each field, `MockRun` with the config written to
  `inputs/rotate.yaml` (the sweep skips that directory; the working
  directory is `work/`, so `--config` gets the absolute path) as
  `https://admin:<canary>@api.example.com`, plus
  `http://admin:<canary>@localhost:4873`; `-vvv --config <path> plan
  --stdin` with `RUST_LOG=trace` exits 2 and the `Sweep` (stdout, stderr,
  every file under the root, every encoding) finds no canary. The error's
  path is the config path, which holds no canary.

Checked by mutation: with the userinfo rule removed, T3 and T8 fail; with
the loopback check reduced to a prefix test, T3 fails; with the warning
left out of `render_at` or `render_json`, T4 and T6 fail.
