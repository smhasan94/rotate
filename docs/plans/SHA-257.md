# Implementation plan: SHA-257 manual replacement mode

Ticket edits applied with this plan:

- `manual_instructions` takes the scope: `fn manual_instructions(&self,
  scope: &Scope) -> String`, with a default impl ("Create a new <provider>
  credential for <identity> with the same access as the leaked one, then
  paste it at the prompt.") so existing providers compile unchanged. The
  GitHub, npm and OpenAI providers (SHA-260, SHA-261, SHA-262) override it
  to name the page and the scopes.
- Hidden input uses `rustix` (`termios` feature), not `rpassword`. rustix
  is already in the lock file (through `tempfile`), is Apache-2.0 OR MIT,
  and gives a safe `tcgetattr`/`tcsetattr` API, so the crate keeps
  `#![deny(unsafe_code)]`. rpassword would add two crates and returns a
  `String` that is grown by `read_line`, leaving unwiped copies; reading
  byte by byte into a pre-reserved `Zeroizing<Vec<u8>>` avoids that.
- "Identity check" means `verify(new, scope.identity)` succeeds. Any
  `verify` error counts as a rejected paste (wrong account, revoked, typo).
  A paste equal to the leaked secret (same fingerprint) and an empty paste
  are rejected without a call. Each counts as one of the three attempts.
- `--replacement-from-env <VAR>` and `--replacement-file <PATH>` conflict
  with each other and give exactly one attempt: a rejected value fails the
  rotation at create. They are read once, at the start of `apply`, before
  the state file is opened or any provider call, so a refusal (unset or
  empty variable, file with any group or other permission bit, not a
  regular file) exits 2 with zero calls. Errors never repeat the variable
  name or the path. One supplied value serves one rotation: if more than
  one manual rotation is confirmed with a supplied value, apply exits 2
  before any mutating call. A supplied value with no manual rotation is
  ignored with a note.
- An AWS-style key pair (a provider whose credential is a pair) is pasted
  as `KEY_ID:SECRET`. No MVP provider needs it; it keeps the type complete.
- Audit: the `create` entry gains `replacement_mode` (`automatic` or
  `manual`), an optional field (audit version stays 1; older readers of a
  newer log are not a supported case pre-1.0). The plan already shows the
  mode (`manual: you will be asked to paste the new secret`, JSON
  `"mode": "manual"`).
- No terminal and no supplied value: the rotation fails at create with "no
  terminal to paste the replacement on; pass --replacement-from-env <VAR>
  or --replacement-file <PATH>", exit 1, nothing changed.
- Fix carried here because the hidden prompt depends on it: the apply
  confirmation question was written through a buffered console writer that
  only prints on drop, so it appeared after the answer was read. Questions
  now go through `apply::Terminal::err`, one redacted message per call,
  printed before the read.

## Approach

`src/provider/mod.rs`: `Provider::manual_instructions(&self, &Scope) ->
String` with the default above.

`src/apply.rs`:

- `pub trait Terminal { fn out(&mut self, text: &str); fn err(&mut self, text: &str); }`,
  implemented for `Console`. Each call is one redacted message, written at
  once.
- `Prompt` gains `fn read_secret(&mut self, question: &str, term: &mut dyn Terminal) -> Result<SecretValue, PromptError>`.
  `TtyPrompt` opens the terminal, turns `ECHO` off with rustix, writes the
  question, reads one line byte by byte into zeroized memory (max 4096
  bytes), restores the saved mode (also on error, through a drop guard),
  then writes a newline. `TtyPrompt::with_path` reads another terminal
  device (the pty test). `ScriptedPrompt` pops the next answer.
  `PromptError::NoTerminalForSecret` is the message above.
- `pub enum ReplacementSource { Prompt(Box<dyn Prompt>), Supplied(Option<SecretValue>) }`
  and `Executor::with_manual(source, &mut dyn Terminal)`.
- In `steps`, the create step branches on `rotation.replacement_mode`:
  automatic calls `create_replacement` as before; manual prints the
  instructions to stdout, then up to three attempts (one for a supplied
  value): read, parse into a `Credential` of the leaked one's shape,
  reject a paste equal to the leaked secret, `verify(new, identity)`. A
  rejection writes "the pasted secret was rejected: <error>; try again
  (attempt n of 3)" to stderr. Success records `created` with
  `replacement_ref = "manual"` and the fingerprint; three rejections mark
  the rotation `failed` at create. No consumer is touched before success.
  The later verify step runs unchanged.
- `Ineligible::Manual` is removed; manual rotations are confirmed and run.

`src/input.rs`: `replacement_from_env`, `replacement_from_file` (fstat on
the opened file: regular, mode & 0o077 == 0), `normalize` (drop one
trailing newline, reject blank) and `replacement_credential(value, like)`.
`ReplacementInputError` never holds the name, path or value.

`src/audit.rs`: `AuditEvent::with_mode`, `AuditEntry::replacement_mode`.

`src/cli.rs`: `ApplyArgs` gains the two flags (conflicting).

`src/main.rs`: read the supplied replacement first; after confirmation
check the one-value rule; pass the source and console to the executor;
confirmation through `Terminal`.

`src/providers.rs` (feature `test-providers`): `PanicPrompt` and `NoTty`
implement `read_secret`; scenario `prompt: {"tty": "<device>"}` uses
`TtyPrompt::with_path`; `providers.<name>.foreign: ["sha256:..."]` makes
`verify` report those credentials as owned by another identity
(`MockProvider::owner`).

## Secret handling

The pasted value goes from the terminal (or the variable, or the file)
straight into a `SecretValue`: registered with the redactor at once, wiped
on drop. The tty read uses a pre-reserved buffer so it never reallocates;
input longer than 4096 bytes is refused. Echo is off for the whole read and
restored by a guard. Mismatch messages carry the provider's error text,
which the provider contract already keeps value-free, and go through the
redacting console. State and audit hold `replacement_ref = "manual"` and
fingerprints only. Errors about the file or variable name neither.

## Risks

- SHA-256 edits `revoke_gate`, the summary and `main.rs` apply; this
  ticket touches only the create step and the confirmation writer there.
- pty behaviour differs between macOS and Linux; the test opens the
  device itself, waits for the question on stderr before typing, and has
  a watchdog.

## Out of scope

Automating token creation, the real GitHub and npm providers, resume of a
failed manual rotation (SHA-258).
