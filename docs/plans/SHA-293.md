# Implementation plan: SHA-293 leakage sweep for revoke_manual and plan --check-permissions

Two output paths landed beside SHA-265 and are not in its sweep: the
`revoke_manual` step (SHA-289) and `rotate plan --check-permissions`
(SHA-270). This ticket adds `Sweep` runs for both to `tests/leakage.rs`,
reusing `MockRun` (npm mock) and `RealRun` (the `tests/e2e` wiremock
harness with canary values). No new sweep encodings.

## revoke_manual runs (T1, AC1)

`MockRun` with two variants of the npm mock:

- `manual_revoke` set: the provider says up front it cannot revoke.
- `unsupported.revoke` set: revoke is attempted and refused as
  `Unsupported`.

In both, the instruction text the provider returns echoes the old secret
and the mock replacement, as an upstream that quotes the key would. That
text reaches stdout, the `revoke_instructions` field of the state file, the
skipped `revoke` audit entry and the `status` hint, so it is the place a
leak would show.

Sequence per variant: plan, apply (exit 4, step `revoke_manual`), `status`,
`status --all`, `--json status`, re-apply while the old secret is still
valid (exit 4 again), then mark it invalid: plan (the `revoked by hand`
skip), apply (exit 0, step `revoked`), `--json status --all`. Every run is
swept: stdout, stderr at `-vvv` + `RUST_LOG=trace`, and every file under
the run root.

## check-permissions runs (T2, AC2)

`RealRun` with the real AWS and GitHub plugins. The e2e models gain two
injections:

- `State::simulate_error: Option<(u16, String)>`: answer
  `iam:SimulatePrincipalPolicy` with that status and an XML error whose
  message is the given text.
- `GithubState::public_key_error: Option<(u16, String)>`: answer
  `GET .../public-key` with that status and a JSON `message`.

Runs (each `plan --check-permissions` in table and `--json` form):

1. all actions allowed (the documented policy, as in `permissions_e2e`);
2. one action denied (`iam:CreateAccessKey` removed);
3. the simulate call failing with 500 and a message echoing the operator
   AWS secret (and its access key id context);
4. the public-key read returning 403 with the GitHub token in the body;
5. the public-key read returning 500 with the GitHub token in the body.

The requests the mocks received are also checked: no operator credential
in a body or URL (`RealRun::assert_requests_clean`).

## Leaks (T3, AC3)

If a run finds a leak, fix it where the error text is built, while the
credential is still registered with the redactor (as SHA-265 did in
`src/assess.rs`), and add a unit test next to the fix that asserts the text
is redacted. Otherwise no `src/` change.

## T4

T1 and T2 are the proof that no secret appears in stdout, stderr, tracing
output, the audit log or the state file. The planted-leak self-test
(SHA-265 T2) runs unchanged in the same file.
